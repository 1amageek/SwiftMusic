# Playback

## Purpose and Scope
Component. Parent: [Core](../DESIGN.md). Children: none.

## Responsibilities and Boundaries
AudioLoopEngine owns AVAudioEngine, revision-safe sample transport, live master processing, and bounded post-FX capture. Shared state is Mutex-protected on every access. App changes playback only through MainActor control APIs.

## Related Designs
Use the parent/child links above. Dependencies: SwiftMusic owns event semantics; Core owns rendering/playback/evaluation contracts; App consumes Core.

## Architecture
```text
prepared loop -> SourceNode -> TimePitch -> low-pass EQ -> Delay -> Reverb -> mainMixer
                    |                                               |
revision/bar adoption + live rate                         bounded stereo tap -> snapshot
```

## Contracts and Invariants
Public @MainActor engine: init() throws; beginUpdate(revision: UInt64); submit(loop: PreparedLoop, revision: UInt64) throws; play() throws; stop(); snapshot() -> PlaybackSnapshot. Snapshot fields loop: PreparedLoop?, revision: UInt64?, beatPosition: Double, isPlaying: Bool. New edit clears pending but preserves current. Reject stale/duplicate completions. First loop adopts while stopped. Existing playing loop adopts at next current-meter bar boundary without resetting the accumulated transport clock. Snapshot reports actual adopted PCM. Callback copies bounded PCM, no await/UI/I/O. Immutable buffers retain an off-callback owner to prevent deallocation on callback.

Live MainActor controls are `setPlaybackRate(_ rate: Float) throws`, `setLowPass(cutoff: Float?) throws`, `setDelay(mix: Float) throws`, `setReverb(mix: Float) throws`, and `outputMeter() -> OutputMeterSnapshot`. The generic engine defaults to rate 1; SessionModel supplies `liveBPM / 120` because its loops use a fixed 120 BPM preparation base. A nil cutoff bypasses EQ; a cutoff must be finite within 20...20,000 Hz. Delay and reverb mixes are normalized finite 0...1 values converted to native wet percentages. Neutral defaults are rate 1, bypassed EQ, and zero wet mix. Invalid controls fail explicitly and retain the last valid settings.

`AudioLoopEngine.validateMasterControl(_ parameter: LiveControlParameter, value: Float) throws` is the public static, nonmutating admission query for numeric master Learn-range endpoints. It accepts playback rate only within finite 1/32...32, low-pass cutoff within finite 20...20,000 Hz, and delay/reverb mixes within finite 0...1; unsupported parameters and invalid values fail typed. Every corresponding setter calls the same validator before changing target, smoothing task or native state. The App therefore does not clamp a saved Learn range to its suggested viewport or duplicate native master rules.

P04 keeps these APIs and native TimePitch -> EQ -> Delay -> Reverb ownership. While transport is playing, one MainActor `MasterParameterSmoother` applies each accepted target over three linear 10-millisecond intervals using `ContinuousClock`, for a fixed 30-millisecond transition and 100 Hz native writes. Parameters own independent tasks. A newer value for the same parameter cancels only that task and starts from its last applied interpolated value. While transport is stopped, no audible transition exists: an accepted target cancels its parameter task and applies the final native value synchronously, which also keeps existing configure-then-offline-render callers deterministic without MainActor starvation. Validation occurs before changing target/task state and cancellation is not reported as a control failure. Native properties are written only on MainActor, never from the audio callback or under the transport/output-meter Mutex. The internal smoother injects an `@MainActor @Sendable (Duration) async throws(CancellationError) -> Void` sleep closure. Its production adapter alone calls the untyped-throwing `ContinuousClock.sleep(for:)`: `CancellationError` is forwarded, while any non-cancellation error is an explicit internal invariant failure and is never rounded to elapsed time or cancellation. Focused tests drive a typed-cancellation closure and observe applied steps without a public clock protocol, failure channel or configuration API. P05 may add automation precedence without changing this base transition owner.

Low-pass enable and disable have explicit transition state. Enabling from bypass first sets 20,000 Hz and clears bypass, then ramps to the requested cutoff. Changing an enabled cutoff ramps from the last applied frequency. Disabling an enabled filter ramps to 20,000 Hz and sets bypass only after the final step; replacement before that step keeps the filter enabled and starts from the current frequency. A nil target while already bypassed is a no-op. Stopped application of nil bypasses synchronously.

Playback-rate smoothing changes only TimePitch rate. It neither reevaluates source nor resets `framePosition`, accumulated beat position, current/pending revision, effect state or the bar-adoption boundary. Transport remains measured in the prepared loop's source beats; snapshot latency correction uses the current interpolated rate. Delay/reverb master tails remain native post-loop output and post-FX meter data, while code-declared deterministic tails are already part of PreparedLoop. Invalid controls, edit/evaluation/render failure and stale submission preserve the current adopted loop, in-flight ramps and last valid master targets. `stop()` cancels every task and synchronously snaps each native property to its last valid target while inaudible, so the next play starts from the requested state; it does not clear those targets. Engine deinitialization cancels every task before removing the tap and stopping/releasing the graph, and canceled tasks check cancellation before every native write.

P04 playback verification proves exact 10/20/30-millisecond monotonic steps, independent parameters and replacement from an in-flight value; immediate stopped configuration; low-pass 20 kHz enable/disable transitions and bypass timing; no source revision/evaluation on controls; phase-preserving rate change; current-meter boundary adoption during a rate ramp; invalid/stale failure preservation; stop snap-to-target and deinit cancellation with no later native write; native master tail and post-FX meter behavior; and callback isolation. A native actual-output fixture distinguishes smoothed controls from a step while retaining pitch through tempo change.

One main-mixer tap copies at most the latest 2,048 stereo Float frames and actual sample rate into preallocated Mutex-protected storage. `OutputMeterSnapshot` exposes `interleavedSamples: [Float]` and `sampleRate: Double`; the owned array has exactly 4,096 values when active and zeros while stopped. The callback performs bounded copy only. Snapshot/FFT work occurs off callback. This signal is after the owned effects and before hardware volume or room acoustics. Display beat position compensates valid engine output-presentation and unit latency; invalid latency metadata fails or is excluded explicitly rather than producing nonfinite positions.

### P05 control precedence boundary

This section is the sole authority for live precedence. P05.1 keeps source/subtree automation descriptors in CompiledSound even though LoopRenderer produces immutable PCM. P05.7 makes source/subtree gain, pan, pitch and cutoff, track level/pan, and the existing native master rate, low-pass cutoff, delay mix and reverb mix runtime-addressable only after their concrete path is implemented. No editor control may report an address as live merely because a descriptor exists.

The public control DTOs are Codable, Sendable and Equatable. `LiveControlTarget` is `.source(Int)`, `.renderNode(Int)`, `.track(Int)` or `.master`; `LiveControlParameter` is `.gain`, `.pan`, `.pitchOffsetSemitones`, `.cutoffHz`, `.trackLevel`, `.trackPan`, `.playbackRate`, `.lowPassCutoff`, `.delayMix` or `.reverbMix`. `LiveControlAddress` stores `revision: UInt64`, `target` and `parameter`. `LiveControlValue` is `.number(Double)` or `.bypassed`; bypass is accepted only for master low-pass and a nil Track pan. `LiveControlBaseline` is `.scalar(Double)`, `.bypassed` or `.automation`. `LiveControlOverride` stores one address and value. `LiveControlDescriptor` stores the address, display label and `LiveControlBaseline` without exposing compiler internals. The catalog contains unique addresses in source, render-node, Track, then master order. The complete active override array is unique by address; omission releases an earlier override.

For source, subtree and track addresses, the adopted persistent evaluation worker owns the bounded `CompiledSound` and reusable render session needed to reproduce PCM; the host owns only the Codable catalog, PreparedLoop values and the worker handle. An address is `(adoptedRevision, targetKind, compiledID, parameter)` and is valid only within that revision. Source IDs expose gain, pan, pitch-offset and cutoff targets; gain/pan or gain/pan-automation render-node IDs expose their subtree parameter; Track IDs expose level and pan. A source gain/pan override processes that source boundary before later graph nodes. A subtree override replaces only the addressed gain/pan node's scalar or automation output. A Track override replaces only the addressed Track level/pan. A pitch override replaces that source's continuous pitch-automation value while preserving event pitch, static transpose, pitch envelope and tuning; cutoff similarly replaces continuous cutoff automation while preserving the declared filter kind, Q and filter envelope. Gain/level are finite and nonnegative, pan is finite in -1...1, pitch offset must keep every effective pitched event in 0...127 and renderer frequencies valid, and cutoff is finite in 20..<22,050 Hz. Unsupported target/parameter pairs and duplicate addresses fail before rendering.

`AudioLoopEngine.replace(loop:revision:generation:)` accepts a same-code-revision PCM replacement only after validating identical sample rate, BPM, meter, beat count, frame count, event count/order and each event's source ID, label, onset, velocity and pattern-step provenance, plus stable row ID/label/anchor/result-line/pattern text. Audible duration/wrap, MIDI, gain, pan, samples and row peaks may change because pitch and amplitude controls change the actual rendered result; ordinary PreparedLoop validation still owns their bounds. The retained CompiledSound overlay owner, rather than host metadata comparison, proves unchanged compiler topology. A generation must be newer than the current or queued override generation. Replacement keeps accumulated beat time and maps the current normalized frame into the new circular buffer.

The callback applies a complementary linear old/new crossfade for exactly 30 milliseconds at 44.1 kHz; a replacement received during that fade replaces one latest override slot and begins after the current fade, never blending a blend. Transport owns at most current, fading-old, latest override and one code-revision pending loop, plus one completed-fade retirement slot. Fade completion moves the old loop into that fixed slot without releasing it on callback; a subsequent fade waits until the MainActor engine drains the slot and releases it off callback. Replacing either pending slot occurs on MainActor and releases the displaced value there. `PlaybackSnapshot` reports the adopted code revision and active override generation separately, so an override never masquerades as a source edit. Shape, stale-generation or bound failure mutates no transport state.

Native master addresses continue through the P04 MainActor properties and smoother without PCM rerender. Their last valid rate, low-pass, delay and reverb targets are performance state owned by AudioLoopEngine/SessionModel, independent of a compiled score revision; successful or failed code evaluation never resets them. The host appends master descriptors to the worker catalog using those current targets as their baseline, rather than asking the worker graph to invent master state. A newly adopted code revision invalidates the old master addresses, issues fresh addresses for the same native owners and preserves their target values without another setter call or audible transition. An old-revision master request is stale. Releasing a temporary master gesture returns to the host-owned persistent target; it never resets to rate one, bypass/zero defaults merely because code changed.

Across both paths the active knob/XY gesture is the top layer, adopted code automation is next, and its adopted code scalar is the baseline; automation phase continues while overridden because every rerender starts from the retained code result rather than the prior overridden result. Release removes only that source/node/Track address from the overlay set and rerenders the baseline/remaining overlays. Failed/stale code evaluation retains the adopted worker, graph, PCM and active overlay. A newly adopted code revision atomically switches loop and worker at its bar boundary, releases every source/node/Track overlay, invalidates every prior address and generation, and shuts down the old worker only after transport no longer owns its PCM; compiled IDs are never remapped by position. The master-state rebinding above is the sole semantic-address exception and does not preserve an old handle. P05.7 owns worker protocol/lifetime, latest-generation cancellation, crossfade state and its resource evidence. P05.1 only guarantees complete descriptors and adds no callable future API.

### P06.3 MIDI clock boundary

`PlaybackClockAnchor` contains Core Audio `presentationHostTime`, unwrapped `accumulatedBeatPosition`, effective `beatsPerMinute`, `loopBeatCount`, adopted `revision`, `overrideGeneration` and `isPlaying`. While playing, `AudioLoopEngine.playbackClockAnchor()` throws `PlaybackClockError.unavailable` until the source callback has supplied a valid host timestamp. Playback pairs the raw accumulated beat at the source render boundary with that host timestamp advanced by the one authoritative downstream output-presentation latency; it does not subtract latency beats or clamp an initial negative beat. TimePitch rate determines effective beats per minute for extrapolation after that pair. This represents the future host instant at which that raw beat becomes audible and is the host-time form of the UI's latency-corrected cursor. Loop wrap changes only the local remainder; code adoption and same-revision replacement preserve accumulated beat but invalidate the timestamp sample until the next valid callback. Stop returns a nonplaying anchor that pairs the frozen accumulated beat with current `mach_absolute_time`; it never fabricates forward motion.

Its public throwing initializer validates nonzero presentation host time, finite nonnegative accumulated beat, and finite positive effective BPM and loop length. Revision and generation are engine-owned identity values preserved verbatim; a standalone value has no prior state against which to validate them. `beat(atHostTime:) throws -> Double` uses checked signed relative ticks with `AVAudioTime.seconds(forHostTime:)`; while stopped it returns the frozen accumulated beat for every queried timestamp. A playing query that would precede beat zero fails `.outOfRange` rather than clamping startup time. `hostTime(atBeat:) throws -> UInt64` requires a playing anchor and accepts a nonnegative target beat within one physical second on either side of the anchor beat, using checked host-tick addition or subtraction. This symmetric conversion is required because the latest source-render beat is ahead of audible now while its earlier beat can still have a future presentation timestamp. Arithmetic underflow/overflow and a larger separation fail typed. The value stores no duplicate timebase. MIDI ingress uses the same one-second window; the MIDI send boundary separately requires the computed host time to be between current `mach_absolute_time` and one second ahead so a backward beat projection can be scheduled only while it is still physically in the future.

The source callback records its host-time/accumulated-beat pair in existing short Mutex state without calling CoreMIDI, allocating, awaiting or invoking an external callback. Zero, invalid or nonmonotonic callback host time invalidates the sample. Host ticks convert through the Darwin timebase with checked arithmetic. A rate step, play, adoption, replacement or discontinuous host timestamp invalidates an older extrapolation until the next valid callback; stop produces the frozen anchor above. MIDI consumes immutable anchors and may extrapolate only while `isPlaying`; it does not read AudioTransport internals. `PlaybackClockError.unavailable`, `.discontinuous` and `.outOfRange` distinguish missing sample, excessive timestamp separation and invalid target/arithmetic. Injected callback timestamps and latency prove fixed/rate-scaled mapping, loop wrap, replacement continuity, stopped state and typed unavailable/discontinuity failure before virtual-endpoint composition.

P06.3 composition also adds `AudioLoopEngine.restartFromBeginning() throws`. It requires a current loop, preserves its revision, override generation, PCM and master settings, resets frame and accumulated beat to zero, and starts playback. An existing pending code loop remains pending and its adoption boundary is recalculated from the restarted current meter. MIDI Start uses this operation; MIDI Continue uses ordinary `play()` and preserves position; MIDI Stop uses ordinary `stop()`.

### P06.4 hosted Audio Unit effect slot

AudioLoopEngine implements [AudioUnitHosting](../AudioUnits/DESIGN.md) with exactly one optional effect after the existing TimePitch -> low-pass -> Delay -> Reverb master chain and before the main mixer/post-FX tap. Therefore its output is audible, metered and included in `sourceNode.outputPresentationLatency`; the MIDI clock continues to use that single downstream latency owner. Code-rendered effects and PreparedLoop remain unchanged. Instruments and generators cannot occupy this audio-effect slot.

Selection instantiates and restores a candidate before graph mutation. Before touching the graph, the host admits the candidate by validating its buses and successfully setting the required 44.1-kHz stereo formats through the throwing Audio Unit bus API. On MainActor the engine records whether it was running, stops AVAudioEngine without stopping AudioTransport, then performs attach/connect/prepare only among the engine's known-owned nodes and the admitted candidate; those Objective-C graph operations are precondition-bound and are not falsely promised as catchable Swift failures. A thrown instantiate, state, format-admission or engine-start failure remains typed. Only successful restart commits the descriptor/unit and detaches the old unit. Start failure removes the candidate, reconnects and restarts the retained old graph, and reports the original typed failure; rollback restart failure reports both failures and leaves transport/PCM retained but audio explicitly stopped. Clear uses the same transaction to reconnect Reverb directly to the mixer. Frame and accumulated beat, current/pending revision, override generation, master targets, MIDI route and source worker are never reset by a successful swap. Third-party Objective-C exceptions during graph mutation are outside this in-process host's typed-failure guarantee; the slot does not claim a security-isolation boundary.

The candidate must expose at least one compatible input and output bus and finite nonnegative latency/tail metadata; format admission happens before the old graph is disconnected. `setAudioEffectBypassed` writes only `AUAudioUnit.shouldBypassEffect` on MainActor and preserves selection/state. State capture/restore follows the Audio Units contract and never fabricates an empty state. One selection generation owns an asynchronous instantiate; superseded/timeout candidates cannot mutate the graph. The suspended selection operation retains the engine until its native completion or fixed 10-second timeout, so dropping external references is not promised as prompt cancellation; completion/timeout releases that bounded ownership and permits deinit. Stop preserves the selected unit and document state. Once deinit is reachable it defensively cancels any remaining request, removes the mixer tap, stops the graph, detaches the selected unit and releases it on MainActor.

Focused injected-instantiator tests prove latest-selection lifetime, stopped/running transaction, rollback and double-failure state, bypass/state identity and unchanged transport. Native manual rendering loads one discovered Apple effect, distinguishes its processed PCM and post-FX meter from bypass bit-for-bit within the fixture tolerance, restores captured state into a fresh instance, and proves an unsupported instrument or failed candidate leaves the prior audible graph and playback position. Release/native composition is the final capability gate; descriptor/unit construction alone is insufficient.

### P06.5 master recording

`MasterRecordingRequest` contains a new destination URL, `.wavFloat32` format and a caller-supplied positive maximum duration. Admission converts that duration to frames with checked arithmetic and requires the stereo Float32 data byte count to fit the WAV data-chunk limit; the format-derived limit is the ceiling rather than an arbitrary session duration. `AudioLoopEngine.startRecording(_:) throws`, `stopRecording() async throws -> MasterRecordingResult` and `cancelRecording() async throws` are MainActor lifecycle operations; one engine owns at most one take. The result reports destination, 44.1-kHz stereo format and exact captured frames. Capture begins with the first accepted buffer after start and records the existing main-mixer tap after native master processing and the hosted Audio Unit, before hardware volume, exactly once. Canceling an active take waits for the writer and successful temporary-file removal; writer or cleanup failure throws `MasterRecordingError.fileFailure`. Cancel with no active take is idempotent success. `stopRecording` retains its original recording failure and includes any cleanup diagnostic instead of replacing or hiding either cause.

The existing main-mixer tap keeps `format: nil`: its callback format is the mixer/output route's actual native format, and the requested 2,048-frame tap buffer size is not treated as a frame-length or sample-rate guarantee. One callback validates finite positive sample rate, Float PCM and one or two channels, then splits its complete `frameLength` in order into as many preallocated recording blocks as required, each holding at most 2,048 frames. It never truncates to the meter's latest-window capacity. Every block carries the take's actual source format and sample-time range. The first block fixes that take's format; a later format change, missing sample time or noncontiguous sample-time range is a typed discontinuity and no later frame is accepted. The writer duplicates admitted mono into stereo and maps stereo directly; a wider mixer layout is an explicit unsupported-format recording failure while playback and metering continue.

The engine owns one persistent recording pool whose 64 slots are fixed planar Float storage plus scalar format/sample-time metadata. `startRecording` allocates and validates every slot before publishing an active take. The callback attempts the pool's native Mutex with `withLockIfAvailable` and never waits; it copies into free Float slots only. Lock contention, insufficient free slots or a callback requiring more blocks than remain sets the take's Atomic failure exactly once, accepts no later frames and ultimately returns a typed recording failure rather than publishing truncated capture. The callback otherwise performs bounded copy and never allocates, converts sample rate, writes a file or invokes an external callback.

The writer task alone owns bounded native buffers: one captured-input `AVAudioPCMBuffer` with 2,048-frame capacity, one 2,048-frame converter input scratch buffer that presents the exact requested slice count, and one converter output buffer with 8,192-frame capacity, plus its `AVAudioConverter` and `AVAudioFile`. Under one short Mutex section it copies the next ready Float slot into the captured-input buffer and releases that slot; slice preparation, conversion and file I/O then occur outside the lock. These `AVAudioPCMBuffer` values are non-Sendable and never cross the callback/Mutex/writer isolation boundary or require `@unchecked Sendable`/preconcurrency suppression. The extra off-callback copy is the explicit ownership boundary. Channel mapping and sample-rate conversion occur only in the writer. It writes exactly the half-open captured duration, with output frame count `ceil(totalInputFrames * 44_100 / inputSampleRate)` after checked arithmetic and converter drain. Converter setup/status, unsupported layout, pool exhaustion or maximum-frame excess are typed failures. The writer uses an adjacent unique temporary file, closes it and atomically renames only after successful stop. Failure, cancellation, shutdown or deinit attempts to remove the temporary file, preserves playback and never publishes a partial destination; cleanup failure remains thrown/diagnosed through the lifecycle operation. An existing destination fails before capture.

Focused tests inject 44.1/48-kHz buffers whose frame lengths are smaller and larger than 2,048 to prove full ordered splitting, conversion duration, sample-time/format discontinuity, meter coexistence, pool overflow, duration admission, stop drain and cleanup. Native Release evidence records the observed mixer-tap format and frame lengths, captures audible post-Audio-Unit output, reopens the 44.1-kHz stereo WAV and compares its resampled signal with the post-FX meter over the same captured interval.

### P07 performance telemetry

Playback extends its immutable snapshot with bounded master peak/clip state, callback load and a monotonic dropout count. `PlaybackPerformanceSnapshot.callbackLoad` measures the AVAudioSourceNode callback only, excluding native Audio Unit and system CPU work; the UI labels it callback load. The count records source-callback errors/deadline overruns and discontinuous actual mixer sample-time intervals, rather than claiming a hardware-driver xrun counter. Master peak and sticky clipping inspect every frame of the actual mixer tap, including frames outside the 2,048-frame waveform viewport. Absent measurements remain nil. The callback updates preallocated numeric state under the existing short Mutex; load is elapsed host time divided by supplied buffer duration, and a missed/late render increments the count. UI formatting remains off callback. Stop freezes values for inspection, restart retains them, and an explicit diagnostics reset clears them. Track/Bus envelopes come from Rendering rather than the hardware callback.

## Failure, Concurrency, and Constraints
Failure is reported as a diagnostic or typed error; the last adopted loop survives edit failures. Mutable host state is MainActor- or Mutex-isolated.

## Verification and Change Impact
Tests prove render cursor progress through failed/stale updates, boundary changes and stop/resume. Native offline AVAudioEngine tests prove 2x timing with stable pitch, low-pass attenuation, delay/reverb tails, neutral PCM behavior, bounded post-FX capture, paused zero, and latency compensation. Mutex copy callbacks are thread-safe but are not a hard-real-time guarantee. All unsafe audio-buffer borrows are scoped to callbacks and never escape. Shutdown removes the tap and stops the engine before resource release.

### State and platform ownership

| State | Storage / isolation | Read / mutation | Lifetime |
|---|---|---|---|
| Native audio graph and live parameters | MainActor engine | Public controls / snapshot | Engine stop, tap removal, owner release |
| Adopted and pending transport | Mutex<State> | Snapshot / submit / render callback | Engine-owned transport; immutable PCM also retained off callback |
| Post-effect capture | Preallocated Mutex storage | Owned snapshot copy / native tap bounded write | Engine-owned capture; stop disables and clears capture |
| MIDI clock sample | Fields in the same `AudioTransport` Mutex state | Render callback writes host-time/beat; MainActor returns immutable anchor | Invalidated by rate/play/adopt/replace; frozen on stop; released with transport |

This package targets macOS AVFAudio only; it has no WASM or Embedded implementation or conditional synchronization path. No cross-platform synchronization capability is inferred from the native tests.
