# Evaluation

## Purpose and Scope
Component. Parent: [Core](../DESIGN.md). Children: none.

## Responsibilities and Boundaries
SourceEvaluator owns generated SwiftPM evaluation workspace and subprocess lifetime. SwiftCompletionService owns a separate SourceKit-LSP workspace and process. Caller owns edit revisions/debounce and completion presentation.

## Related Designs
Use the parent/child links above. Dependencies: SwiftMusic owns event semantics; Core owns rendering/playback/evaluation contracts; App consumes Core.

## Architecture
```text
Session: Music source -> compiler + JSON AST -> executable -> LoopRenderer -> result-line enrichment -> validated loop
editable Swift -> dedicated SwiftPM workspace -> SourceKit-LSP -> semantic completion result
```

## Contracts and Invariants
Evaluate real Swift, not a DSL text parser. User defines Session: Music. Wrapper uses #sourceLocation Session.swift for diagnostics. Serialize mutable scratch workspace explicitly across actor reentrancy. A cold release build is bounded to 240 seconds; worker ready and execution/render remain bounded to 10 seconds. Diagnostic output is bounded to 1 MiB, result to 16 MiB and source to 64 KiB. The `/usr/bin/python3` descendant-owning launcher drains a pipe in 64 KiB chunks and caps accepted diagnostics before writing. Cancellation or timeout terminates and confirms exit of the complete subprocess descendant tree, including swift-driver children that create a distinct process group, before the launcher exits and before the workspace can be reused. Foundation terminationHandler publishes completion through a Mutex; no blocking wait crosses actor suspension. Decode and validate output before submit. Failed edits leave transport unchanged.

SourceEvaluator accepts an optional explicit runtime-SDK directory at initialization. A packaged App supplies its required bundled runtime SDK; a source/developer/test caller passing nil selects the existing SwiftPM release backend. This is explicit backend selection, not error recovery. An invalid supplied SDK fails with a typed evaluation error and never falls back to a full SwiftPM dependency build.

The runtime SDK contains the release-built SwiftMusic and MusicPlaygourndCore object files, their matching Swift module directories, and a manifest with the exact compiler-version output, macOS SDK path and macro-plugin path from that same app build. The evaluator validates artifact existence, absolute SDK/plugin directories and configured compiler identity once for its immutable SDK/compiler lifetime, retaining only a successfully admitted configuration in actor-owned state. A missing artifact, malformed manifest or compiler mismatch fails explicitly before launching a candidate. The runtime SDK is produced as one build artifact set; source, modules and objects from different builds must not be mixed.

For the supplied-SDK backend, each revision compiles only its generated wrapper using the configured Swift compiler with `-parse-as-library -O`, the manifest SDK, the bundled module search directory and both bundled object files, producing that revision's worker executable. No SwiftPM graph or dependency recompilation runs in this evaluation path. User source remains real Swift; the generated entry, compiler diagnostics, Observation macros and retained worker are unchanged. The JSON-AST frontend uses the same SDK, module and plugin paths as the compiled worker. Existing busy-slot serialization, process-tree cancellation, output and compilation bounds, 10-second worker watchdog, revision gating and last-good-audio retention apply to both backends.

The nil-SDK backend continues to build and locate the SwiftPM release executable and resolve its SDK and compiler plugin paths through bounded discovery commands. A Debug worker is not admissible because per-frame DSP must meet the retained worker's watchdog. Neither backend skips AST or guesses provenance to reduce latency. A native direct-link feasibility probe compiled in 0.4534 seconds and ran SwiftMusic rhythm construction and SpectrumAnalyzer initialization; this proves artifact usability for those operations, not full editor latency or worker compatibility. The final packaged-app workflow measures initial Play and rhythm/notes edits, including actual worker startup and failed-edit retention, without adding tests.

After a successful compile, SourceEvaluator asks the same Swift 6.4 toolchain to emit JSON AST with `-dump-ast -dump-ast-format json`. The AST input contains only the evaluation import prefix plus the unchanged user source, without the generated entry point; the known prefix UTF-8 length maps user Session.swift line/column anchors into compiler byte ranges. For the nil-SDK backend, before that frontend invocation, the evaluator runs `/usr/bin/xcrun --sdk macosx --show-sdk-path` under the same inherited `TOOLCHAINS` environment as the SwiftPM build and validates one absolute existing SDK directory. It passes that path with `-sdk` together with the built module search paths; this is required for frontend imports such as Foundation.URL even though the SwiftPM driver resolves the SDK itself. SDK lookup uses the existing bounded process runner/output/cancellation lifecycle, and failure is a typed evaluation diagnostic with no default SDK or AST fallback. The invocation suppresses warnings so merged diagnostics cannot corrupt successful JSON. For each decoded row with a Session.swift pattern anchor, evaluation selects the outermost explicit `call_expr` containing that bounded UTF-8 byte position and records the expression end line, adjusted back to the user source, as `LoopRow.resultLine`. Implicit calls are excluded. Missing, malformed, ambiguous, oversized, or unsupported AST provenance is a typed evaluation failure; evaluation never guesses chain endings from source text. AST output shares the existing 1 MiB process-output bound and cancellation/process-group lifecycle.

`SwiftCompletionService` is an actor initialized with `packageURL`, `workspace`, and `sourceKitLSPExecutable`. `completions(source:utf16Offset:) async throws -> [SwiftCompletion]` returns semantic candidates with `label`, optional `detail`, `insertion`, a document-relative UTF-16 `replacementRange`, and an insertion-relative optional `selectionRange`; `shutdown()` terminates the server and removes its workspace. The workspace depends on the same bundled SwiftMusic package used by evaluation, but has an independent source file and scratch path. Requests use LSP UTF-16 coordinates at the identifier start, as required by the bundled SourceKit completion engine. The completion-only document omits the typed prefix so SourceKit sees the completion point; the original editor/evaluator source is unchanged. An initial `workspace/synchronize(index: true)` barrier prepares dependencies, with a 60-second bound, without a fixed delay. Subsequent completion requests have a 30-second bound. The service filters labels by the typed prefix and maps the returned replacement through that prefix; it never changes characters outside the server edit and typed prefix. SourceKit snippets are decoded into insertion text and the first argument selection. Malformed ranges or unsupported snippet forms fail or discard the affected candidate instead of applying a guessed edit.

Only the latest source/cursor request may be delivered. Cancellation and bounded timeout cancel the request; protocol failure or server exit returns a typed diagnostic and permits one clean lazy restart. Message size, candidate count, source size, and process lifetime are bounded. Completion never calls SourceEvaluator, allocates an audio revision, submits a loop, or touches adopted audio. Toolchain-specific `sourcekit-lsp` absence is explicit rather than silently switching toolchains.

Evaluation requests `SoundCompiler.compile(_:liveLoop:)` with the current `beatsPerBar`. Its maximum whole-beat horizon is the lesser of `PreparedLoop.maximumBeatCount` and the floor of `PreparedLoop.maximumDurationSeconds * bpm / 60`; the existing validated tempo keeps conversion bounded. The compiler owns exact recurrence and whole-bar selection. Evaluation neither stretches sibling patterns nor truncates events to satisfy the renderer. [Rendering](../Rendering/DESIGN.md) owns PCM window limits and circular voice playback. A common period beyond those limits is a preparation failure and leaves the adopted loop intact. The real evaluation test covers a four-beat pattern with a three-beat bar: twelve beats and three occurrences of the original event template.

### Retained render worker

P05.7 adds `evaluateRetained(source:bpm:beatsPerBar:revision:) async throws -> RetainedEvaluation`, `render(overrides:revision:generation:) async throws -> PreparedLoop`, `@discardableResult adopt(revision:) async -> Bool`, `controlsAvailable(revision:) async -> Bool`, and `discard(revision:) async` alongside the source-compatible one-shot `evaluate`; `RetainedEvaluation` contains the initial located loop and control catalog. `adopt` returns true only when it promotes that candidate or the same healthy revision is already adopted, and false when no promotable/healthy worker exists. `controlsAvailable` returns true only while that revision is the ready adopted connection and is not failed, closing or stopping; an ordinary override validation/render failure leaves it true, while a fatal protocol/process/watchdog fault changes it to false. These lifecycle results are actor-isolated state, not diagnostic-string classification. The render call sends the complete active override set, so removing an address is the release operation. For an ordinary `Session: Music`, the generated executable evaluates `Session()` and compiles it exactly once, creates one `LoopRenderSession`, writes the initial PreparedLoop, control catalog and result-location input, then waits for bounded commands. The performance-model extension below may reevaluate its already-compiled Swift declaration body for an accepted model generation; it never recompiles Swift source or rereads an ordinary body for a P05.7 graph override. The worker alone owns the non-Codable CompiledSound and decoded sample snapshot; neither crosses the process boundary. The host applies AST-derived `resultLine` values to every initial or replacement loop from the retained location map without rerunning the AST frontend. Plain `evaluate` closes its worker after returning, so existing callers cannot accumulate child processes.

The P05.7 base `RenderWorkerCommand` surface is `render(revision:generation:overrides:)`, carrying the complete active override set, plus `shutdown`; P06.5 extends that same framed protocol only with the stem-export operation defined below. Base `RenderWorkerResponse` cases are `ready(revision:catalog:)`, `rendered(revision:generation:)`, `failed(revision:generation:message:)` and `shutdownComplete`, with P06.5 adding its bounded export manifest response; the initial PreparedLoop is generation zero. Every frame is a binary-property-list Codable payload preceded by one unsigned 4-byte big-endian payload length. Zero, a length above 1 MiB, malformed Codable data, an unknown case or EOF inside a frame is a fatal protocol failure. The worker diagnostic message is included inside that same bound. The host parser owns at most the four-byte header and one declared payload, handles arbitrary split/coalesced reads, and never searches user output for a frame.

PCM remains a `WorkerPreparedResult(revision:generation:loop:)` binary property list atomically replaced at one fixed worker-workspace path under the existing 16 MiB result limit. The worker writes and closes that file before `ready`, `rendered` or successful-generation response. The host records `latestRequestedGeneration` before sending each command. Its serialized response owner discards a rendered generation older than that value without reading the shared file; only the response equal to the latest request reads and validates the embedded revision/generation. Therefore generation two can overwrite generation one's file only after the host has already made generation one stale, while a sole generation-one request has no writer that can race it. A mismatch on the latest response is a protocol failure. A `failed` response never changes the file, and no acknowledgement command or per-generation file is required.

The generated `@main` calls public `RenderWorker.run(revision:outputURL:compile:) async throws`, passing a lazy `@MainActor @Sendable () throws -> LoopRenderSession` closure that compiles `Session()` with the wrapper's fixed BPM/meter and returns the retained session. `run` awaits that closure on MainActor only after it duplicates the process's original standard-output descriptor for protocol frames and redirects ordinary stdout and stderr to the bounded worker diagnostic file; prints and diagnostics from user code therefore cannot corrupt responses. An initial setup/compile throw propagates to the generated wrapper's catch, which writes the bounded diagnostic and exits unsuccessfully before advertising ready. Standard input carries commands. One reader remains able to receive a newer render while one cooperative render Task is active; it cancels that Task, keeps only the latest complete command and emits no successful response for a stale generation. Shutdown cancels and awaits rendering, writes `shutdownComplete`, closes protocol descriptors and exits. The ordinary child evaluates Music body and constructs `LoopRenderSession` exactly once; the performance extension owns its explicit reevaluation exception.

Cold build remains bounded to 240 seconds, initial ready to 10 seconds and each override render to 10 seconds. A render that ignores cooperative cancellation until its watchdog, malformed/oversized protocol data, pipe failure or worker exit is a fatal worker fault: the host terminates the worker's complete descendant tree, confirms that distinct-PGID descendants have exited before their discoverable parents, waits for its directly owned child, preserves the last valid PCM, and reports controls unavailable for that adopted revision until a newer code revision is adopted. The same descendant-tree cleanup contract applies to build, AST and SDK-lookup cancellation/timeout. The launcher keeps its owned wrapper alive until this cleanup completes; it does not let an exiting wrapper orphan a compiler descendant. The persistent host connection owns stdin, response pipe, process completion and watchdog independently from the current exit-dependent `processRunner`; it does not route protocol frames through that collector.

Outside a P06.5 export, SourceEvaluator owns at most one adopted worker and one candidate worker. A failed or stale candidate is shut down while the adopted worker and audio continue. SessionModel identifies adoption from the engine snapshot, then promotes that candidate and retires the previous worker after the promotion handshake, except for the one bounded retired-exporter lifetime defined below. PreparedLoop PCM is a self-contained host-owned value, so an AudioTransport fade or pending buffer never extends the worker process lifetime. Opening another document or orderly shutdown closes ordinary workers and removes scratch data after any export cancellation/cleanup contract completes. Invalid address and ordinary render failure preserve the worker, last valid loop and active overlay; fatal worker faults preserve PCM but make controls explicitly unavailable as defined above.

### P06.5 retained stem export

The adopted worker exposes `exportStems(snapshot:operationID:overrides:destination:)` because only that process retains `LoopRenderSession` and prepared assets. `StemExportSnapshot` stores the adopted code revision and fully applied live-control override generation accepted when export starts; `StemExportOperationID` is a private unique operation identity and is never reused as a live-control render generation. One command invokes the Rendering stem boundary once and writes the complete staging directory itself; the framed response contains the operation ID, snapshot identity and bounded stem manifest, never PCM. The destination must be an absolute absent directory outside the worker workspace.

After admission, a newer code revision or control generation does not make the export stale: it completes the immutable accepted snapshot and labels the manifest with that origin. SourceEvaluator retains an old worker with its one in-flight export after newer-code adoption until that operation succeeds, explicitly cancels, times out or fails. At most one export exists process-wide, so lifecycle storage is bounded to current adopted worker, one candidate and one retired exporting worker; the retired worker exposes no live controls. The atomic staging-directory rename is the operation's commit point. Cancellation, orderly shutdown, watchdog, worker failure or host discard observed before rename removes staging and reports failure; once rename succeeds, later cancellation cannot suppress or delete the committed result and the operation returns success with its manifest. Stem export does not replace the shared PreparedLoop result file, adopt a loop or block ordinary stdout collection. The one-shot evaluate path never retains an export owner.

### P07 editor semantic metadata

The retained result adds bounded `EditorSemanticMetadata`: stable sample-bank keys/file display names from the compiled score, compiler-derived `SampleCompletionSite` ranges and the exact adopted control descriptors. A site contains Session.swift UTF-16 content range, source ID and ordered valid values. Its content range may have zero length when the known literal content is empty; the retained delimiters and call identity still prove the site. An edit is content-local when its UTF-16 range begins at or after content start and ends at or before content end, so a zero-length insertion at either content boundary and deletion of the complete content resize and retain the site. An edit that includes a delimiter, lies outside that closed boundary or changes call identity invalidates it until successful evaluation. Metadata contains no decoded sample bytes and is revision-scoped with the catalog. Completion remains SourceKit-LSP authoritative for Swift declarations and edits. `SwiftCompletion` adds optional `CompletionAnnotation` and `SwiftCompletionSemanticKey(label:detail:argumentIndex:)`; unit/range annotation joins only an exact key from the versioned SwiftMusic signature table. Sample-value candidates come only from a mapped adopted site and use that site's exact replacement range, including the zero-length range for an empty literal; this is compiler-owned value completion, not a keyword list or source-text guess. No filesystem scan creates candidates. Metadata admits at most 1,024 sample values, 256 UTF-8 bytes per label and unique identity. A failed edit preserves audio, but annotations and values apply only to the exact completion source snapshot and adopted revision they name.

The generated worker uses SwiftMusic `compileDetailed`; for parameter patterns as well as rhythm/notes it serializes the located declaration anchor, domain and UTF-8 token offset as a bounded structured failure. Evaluation maps that pair through the wrapper/source prefix to a `SourceDiagnosticRange` in Session.swift and keeps typed unsupported/adoption state separate from compiler text. Missing or nonlocal provenance remains a diagnostic without a fabricated range. Protocol-output EOF does not imply diagnostic-output EOF: the connection drains stderr until its EOF before classifying a closed worker. The existing ten-second worker watchdog also bounds this drain, including a passive close with no pending request. Ordinary Swift frontend syntax/type diagnostics remain bounded raw compiler output and do not gain a `SourceDiagnosticRange` by parsing prose; adding a structured Swift-diagnostic transport is outside P07. Tests join real SourceKit results with typed unit/range annotations and mapped adopted bank values, and prove every pattern domain, stale cancellation, Unicode offsets, unsupported capability and the unchanged one-edit completion acceptance path. Sample-site mutation tests delete all content, insert at each empty/nonempty content boundary and still receive adopted bank candidates, while delimiter replacement invalidates the site.

P07.3 composition extends the retained worker framing with one visualization command carrying revision, selection generation, address and the complete active overrides, plus success/typed-failure responses containing the bounded `PreparedControlVisualization`. A newer selection cooperatively cancels the older request. It neither writes the shared PreparedLoop file nor changes `latestRequestedGeneration`; render/adoption and visualization therefore cannot masquerade as each other. Fatal framing/process failures retain the same worker-lifecycle behavior, while an unsupported visualization leaves controls and audio available. This plumbing begins after P07.1 and P07.2, so their parallel foundation work does not share worker command/connection/evaluator files.

### Performance-model worker bridge

The generated wrapper keeps the existing `Session: Music` path. When `Session: PerformanceEntry`, its constrained MainActor helper calls the explicit factory once, resolves `Session().performance(model)`, and retains one `PerformanceObservationSession` for that worker lifetime. Initial and subsequent performance preparations call `prepareDetailed(liveLoop:)` directly, so each request evaluates body once under Observation and preserves `LocatedSoundCompilationError` for the existing source-range mapper; the worker never calls nonthrowing `prepare` and then recompiles to recover provenance. It never reflects a constructor or serializes an arbitrary Observable object. A controllable model contributes only its declared wire descriptors and values; an unmapped observed property may recompile native in-process music but is explicitly unavailable for cross-process control or retention.

The retained protocol adds one complete performance-control request identified by revision and a generation independent of the P05.7 overlay and visualization generations. The payload contains stable model/control IDs and only `Double` or `SpatialPosition` values. `SourceEvaluator.renderPerformance(values:revision:generation:) async throws -> RetainedEvaluation` asks the worker to validate the complete candidate set, temporarily apply all key-path mutations on MainActor, update the `.beatsPerMinute` role as the render session's shared tempo, reevaluate body once, compile and render once, and return a candidate without making it accepted state. Existing P05.7 graph overlays are applied after that candidate's new compiled baseline; neither path silently overrides the other's generation.

Worker and host each retain at most one accepted performance state and one latest pending candidate. `adoptPerformance(revision:generation:) async -> Bool` commits only that exact pending worker model/session after the host has admitted its PCM into Playback's staged replacement slot; `discardPerformance(revision:generation:) async` rolls it back and releases it. A true acknowledgement moves the host copy only to acknowledged-pending state. `SourceEvaluator.confirmPerformance(revision:generation:) -> Bool` performs no worker or file I/O and promotes that exact acknowledged generation to the host's last-audibly-accepted mapped snapshot only after SessionModel observes the matching completed Playback performance generation; absent, stale, unacknowledged and duplicate-after-replacement values return false without mutation. A newer request first discards a superseded unacknowledged candidate and is based on accepted worker state, never on an unaccepted render. Recoverable validation, compiler, sample, renderer or cooperative-cancellation failure restores the accepted mapped values in the still-live worker. A body trap, process exit, protocol fault or noncooperative ready/render timeout is instead the existing fatal worker failure: the host kills and reaps that worker, retains its own last-audibly-accepted mapped-value snapshot and PCM, and marks controls unavailable. It neither claims that the destroyed child model was restored nor silently starts a replacement worker; a later valid code evaluation owns recovery. A successful render response or worker acknowledgement alone never advances hot-edit transfer authority.

On a hot code edit in the same open document session, SourceEvaluator may seed a candidate worker from the host's last audibly accepted mapped values only when stable model ID, complete control IDs, domains, roles and ranges match exactly. A rendered, staged, acknowledged-but-unconfirmed or superseded candidate has no transfer authority. Source digest equality is not required for this in-session transfer. Opening another document or restoring persisted state continues to use the Editor sidecar's digest rule. Unmapped model fields cannot cross worker replacement. A candidate receives the complete compatible mapped state and produces valid PCM before transport adoption; incompatibility keeps its source-declared initial values and reports the typed mismatch in `RetainedEvaluation.performanceTransferIssue` rather than partially injecting state. Compatible seeding uses one private worker generation before code adoption; the evaluator offsets subsequent public performance generations with checked arithmetic so each new source revision still starts its UI generation independently. Worker framing and output retain their existing 1 MiB and 16 MiB bounds and latest-only cancellation/fatal cleanup behavior.

SourceEvaluator retains the bounded source/AST result-location map already produced for that code revision. A performance candidate whose body changes event/row shape is remapped by its compiler source identity and anchor against that cached map before staging; unknown, inconsistent or out-of-bounds identity is a typed candidate failure. No performance generation reruns the Swift frontend or parses source prose. `LoopRenderSession` construction renders its baseline once from the single body/compile result; when the accepted complete P05.7 overlay set is nonempty, rendering that overlay may perform one additional render from the same immutable session only after the Rendering-owned graph-identity admission succeeds. A topology mismatch rejects the candidate while the accepted worker and PCM remain authoritative; an empty overlay does not impose that identity constraint. It never reevaluates body for the overlay and introduces no second cache abstraction.

## Failure, Concurrency, and Constraints
Failure is reported as a diagnostic or typed error; the last adopted loop survives edit failures. Mutable host state is MainActor- or Mutex-isolated.

## Verification and Change Impact
Integration tests execute evaluation success, syntax error, invalid pattern, runtime timeout, cancellation and recovery. A real rooted file/bank source importing Foundation.URL proves that the release SwiftPM build and JSON-AST frontend share the resolved SDK and release module paths, then composes sample selection, pitch/source DSP and voice policy through native rendering. A separate real advanced-synthesis fixture exercises colored noise, multiple voices and effects through the generated release worker and reaches ready plus rendered output inside the unchanged 10-second bounds; neither a pure lower-level PCM test nor a successful Debug build substitutes for this evidence. A cold-build fixture permits the 240-second compile budget; a fixture that also proves cancellation/recovery may use a six-minute Swift Testing limit while preserving every production watchdog. Cancellation and compile timeout capture descendant identities before cleanup and prove that the wrapper, swift frontend, driver and linker descendants, including distinct process groups, have all exited before workspace reuse. SDK lookup/frontend/configuration failure remains visible and preserves the adopted revision. Completion integration opens the real package and proves SwiftMusic modifier/type overloads, including gain signatures, replacement ranges and first-argument selection; it also proves stale/cancel/failure recovery and bounded shutdown without orphan processes. Native compiler/LSP failure is visible, never an empty successful result. Process-specific Application Support workspaces are excluded from Git and independently removed on orderly shutdown. Crash leftovers are not automatically pruned.

### Source line anchors
SourceLineMap owns UTF-16 offsets for the union of compiler-provided Session.swift pattern lines and AST-derived result lines. Native edit ranges are applied before text mutation; unaffected anchors shift by the replacement length delta, anchors removed by an edit become unmapped, and current line lookup uses native newline semantics. Pattern and result lookup remain separate so edits cannot substitute one placement authority for the other. Source is bounded by the editor 64 KiB evaluation limit. Tests cover insertion, deletion, Unicode, stale revisions, and independently shifted/removed pattern and result anchors. App owns maps for current and pending revisions; opening a different document clears associations.

PlayingLiteral maps the adopted compiler leaf index to the exact direct-literal UTF-16 range without parsing musical semantics. ASCII `<`, `>`, `[`, `]` and whitespace delimit structure and never form a leaf. A repetition suffix such as `*3` and comma-separated simultaneous notes remain part of one lexical leaf, matching SwiftMusic's single compiler index for all occurrences or pitches from that token. The literal is first identified by the existing exact source-line rule, then UTF-8 compiler/source offsets are converted through the current source snapshot into native UTF-16 ranges. Escaped, multiline, ambiguous, edited or nonliteral text remains unmapped rather than guessed. VisualFeedbackTests own nested delimiters, repeat/chord leaf ranges, Unicode-prefix conversion and phantom-token rejection.
