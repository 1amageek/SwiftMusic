# Rendering

## Purpose and Scope
Component. Parent: [Core](../DESIGN.md). Children: none.

## Responsibilities and Boundaries
LoopRenderer owns offline PCM synthesis and graph processing. It consumes SwiftMusic CompiledSound and produces both PCM and visual events.

## Related Designs
Use the parent/child links above. Dependencies: SwiftMusic owns event semantics; Core owns rendering/playback/evaluation contracts; App consumes Core.

## Architecture
```text
CompiledSound + bpm + beatsPerBar -> validation -> sources -> ordered graph -> PreparedLoop
```

## Contracts and Invariants
API: LoopRenderer().render(_ sound: CompiledSound, bpm: Double, beatsPerBar: Int) throws -> PreparedLoop. BPM 40...240; quarter-note meter 2...7. Pad extent to whole bars. Duration <=16 seconds, extent <=32 beats, sources/rows <=32, events <=1024, nodes <=256; fail before unbounded allocation. Implemented source descriptors, envelopes, filters, rooted file/bank traversal and voice policy are defined below; Synth sine/square/saw/triangle/noise and procedural kick/snare/closedHat retain their declared capability boundaries. Gain/pan/mute render nodes are supported. P04 adds only the effect and track nodes named in its section; every remaining effect/routing node fails with a typed error and no fallback. Event/source release, decoded-asset exhaustion, voice termination and declared finite effect tails use their owned bounded horizons.

## Failure, Concurrency, and Constraints
Failure is reported as a diagnostic or typed error; the last adopted loop survives edit failures. Mutable host state is MainActor- or Mutex-isolated.

## Verification and Change Impact
Tests compare audible PCM, silence, gain/pan, timing, invalid feature and bound failures. Document any actual signal/tail ceilings. Memory bounded per-node via frame/node work budget.

### Visual signal contract
PreparedLoop.rows retains each compiled source and its optional compiler pattern anchor even when no events fire. `LoopRow.resultLine` is an optional positive Session.swift line populated by SourceEvaluator from compiler AST provenance; optionality preserves standalone renderer construction, while successfully evaluated anchored rows must have it before submission. Each row carries at most 512 peak bins derived from the actual pre-mix source PCM; labels explicitly identify the pre-mix signal, which does not imply audible gain or mute state. LoopRow source IDs link to LoopEvent timing, and each event preserves its optional compiled pattern-step index so the adopted transport can identify the exact active token. Validation rejects invalid anchors or result lines, duplicate row IDs, invalid event step indices, nonfinite or negative peaks and excess rows/bins.

PreparedLoop validation uses the same lexical boundary contract as PlayingLiteral: ASCII angle/square brackets and whitespace are structural delimiters, while a leaf's `*count` suffix and comma-separated note members remain one token. It validates each event index against this compiler-compatible token count and never counts punctuation as a phantom sounding step. CyclePatternRenderingTests own compiler-to-LoopEvent indices, complete multi-cycle PCM and out-of-bound failure; VisualFeedbackTests own the matching source ranges.

SpectrumAnalyzer owns a reusable Accelerate complex DFT setup and buffers on MainActor. At most 30 Hz, it analyzes the playback owner's latest bounded 2,048-frame post-FX stereo snapshot using that snapshot's actual sample rate. A Hann window and channel-averaged power prevent opposite-phase stereo cancellation; 96 logarithmic bands cover 20 Hz to 20 kHz, normalized to peak amplitude dBFS with a -90 dB floor. Paused or absent playback displays silence. Analysis is outside the audio callback and reports setup failure. This visualizes the owned master effects output before hardware volume, not prepared PCM, microphone, or hardware loopback. Frequency/amplitude, stereo opposition, silence, sample-rate, and snapshot-bound tests own correctness.

### Patterned per-event gain
SwiftMusic supplies finite, nonnegative CompiledSoundEvent.gain selected at event onset. The renderer multiplies each voice by this gain before mixing and existing ordered scalar gain nodes. Zero renders silence without inventing or removing rhythmic events. The same value is retained in LoopEvent; inactive zero-gain tokens do not glow. Float amplitude overflow produces an explicit invalid-event diagnostic. PCM tests compare onset-aligned nested gain values, silent spans, relative amplitudes and unchanged scalar gain behavior.

### Patterned per-event pan

SwiftMusic supplies optional `CompiledSoundEvent.pan` in `-1...1`, sampled at the exact event onset. Nil bypasses per-event panning and preserves existing centered PCM exactly; every resolved value, including zero, uses the existing scalar pan node's equal-power cosine/sine law before source mixing. LoopRenderer copies the optional value to `LoopEvent.pan`; decoding legacy LoopEvent data without this field yields nil. Final finite-PCM validation and output clamping remain unchanged, and scalar pan render nodes keep their graph order and behavior. Tests compare left/right PCM for endpoints and explicit center, verify nil default and legacy decode compatibility, reject nonfinite/out-of-range decoded values, and retain scalar-pan evidence.

### Native source performance

LoopRenderer consumes SwiftMusic's immutable envelope, per-voice filter, sample-reference, traversal, voice-policy, choke, and event-override metadata. It owns DSP, file decoding through an injected `SampleLoading` protocol, selected-asset caching for one render, deterministic voice allocation, and conversion into PreparedLoop PCM. SwiftMusic remains the authority for musical time and metadata; Playback consumes the finished loop and does not reinterpret source policy.

For an amplitude envelope, the audible horizon includes release after the selected gate/event anchor. The renderer computes the maximum finite release end at the requested BPM before whole-bar padding and applies the existing 32-beat/16-second limits to that complete horizon; it fails instead of clipping an otherwise valid release. In finite mode it enlarges the PreparedLoop to the least whole-bar extent containing that end. In seamless mode the compiler's canonical beatCount remains fixed: a voice may fold its release across beat zero only when the full onset-to-release span is no greater than one window, otherwise rendering fails explicitly. A fold preserves oscillator/sample elapsed time, filter state, ADSR phase and one attack/release; the buffer split introduces no fade or retrigger.

The effective amplitude envelope is event override, then source envelope, then nil. Configured ADSR replaces the legacy symmetric edge fade and follows the SoundComposition curve/release-anchor formula; nil uses the existing edge-fade sample loop byte for byte. For Synthesizer, tuning maps effective MIDI through `frequencyHz * pow(2, (midi - referenceMIDI) / 12)`; absent tuning retains A4=440. A static pitched oscillator without pitch envelope may retain the current elapsed-time phase formula. Pitch-envelope voices integrate phase once per frame from their instantaneous finite positive sub-Nyquist frequency, preserving phase across circular folding.

P03.2 does not assign an invented pitch scale to procedural built-in Sample sources. A built-in Sample may use amplitude Envelope and source filter DSP, but any nonzero pitchOffsetSemitones, source tuning or pitch envelope on it is a typed unsupported source/event setting before PCM allocation. Nil pitch metadata preserves its current procedural waveform byte for byte. P03.3 enables pitch/rate behavior only for decoded file/bank assets carrying an explicit root pitch; it does not change this permanent procedural-source capability boundary. No renderer path silently ignores these fields.

White-noise Synthesizer is likewise physically unpitched: amplitude Envelope and source filtering are supported, but tuning, pitch envelope or nonzero event pitch offset is a typed unsupported source/event setting before PCM allocation. Zero offset with nil tuning/envelope preserves the existing deterministic white-noise path. This is the declared oscillator capability rather than an incomplete pitched-noise fallback.

LoopEvent duration is the full audible onset-to-release end converted to beats at the requested BPM; `wrapsLoopBoundary` follows that duration. With no configured amplitude envelope it retains the current gated audible duration. Timeline/token activity therefore includes an audible configured release without inventing another event or lexical index.

Per-voice source filtering follows the [W3C Audio EQ Cookbook](https://www.w3.org/TR/audio-eq-cookbook/) normalized RBJ biquads in transposed direct form II with Double coefficient/state arithmetic and Float output conversion. Alpha is `sin(w0) / (2 * Q)`; low-pass, high-pass and constant-0-dB-peak band-pass use the documented coefficient sets. `FilterSlope.twelve` and `.twentyFour` denote actual asymptotic attenuation on each rejected-frequency flank: low/high-pass use one/two identical sections, while band-pass uses two/four because one RBJ band-pass section supplies 6 dB/octave on each flank. The declared Q applies to every section, and the four-section maximum is a fixed per-voice bound. Coefficients are recomputed from the filter-envelope cutoff for each frame; both the base cutoff and every reachable modulated endpoint must stay strictly between zero and Nyquist. Each voice/channel owns zero-initialized filter state through its attack, sustain and release, including circular folding. Nonfinite coefficient, state or sample is a typed event failure before successful PreparedLoop return, never a bypass. Filtering precedes amplitude ADSR, velocity, event gain/pan and source mixing; post-mix AudioEffect nodes remain P04.

Nil tuning, amplitude/pitch/filter envelope and filter metadata select the untouched legacy voice loop. This explicit branch is the byte-for-byte compatibility authority; adding the general DSP path must not perturb existing built-in sample or oscillator PCM. Configured-path work remains bounded by frameCount, at most two circular segments per voice and existing event/source limits, with no per-frame collection allocation.

Swift Testing acceptance compares the nil branch byte for byte with the pre-P03 fixture; checks linear and exponential ADSR values at exact attack, decay, anchor and release sample indices including zero-length segments; proves event Envelope overrides source Envelope; and observes finite whole-bar release extension plus seamless release continuity across beat zero and typed failure beyond one window. Frequency tests cover A4 default/tuned reference, fractional pitch offset, a pitch-envelope sweep with continuous phase and sub-Nyquist rejection. Filter tests differentially compare impulse output with the cookbook equations, distinguish low/high/band response, 12/24 dB cascades and declared Q, exercise a filter-envelope sweep, and reject notch, invalid Q/cutoff, nonfinite state and tuning on an unpitched built-in sample. One compiler-to-PreparedLoop fixture retains event metadata/provenance and reaches nonzero native playback; post-mix effects remain unsupported.

P03.3 adds `SampleLoading.load(_ request: SampleLoadRequest) throws -> LoadedSample`, injected by `LoopRenderer.init(sampleLoader:)`. The request contains the canonical absolute file URL, selected `SampleRegion`, `PreparedLoop.requiredSampleRate`, and positive `maximumChannelFrames` remaining in this render's aggregate cache budget; channel frames means decoded frame count multiplied by one or two channels. `LoadedSample` owns finite interleaved Float PCM at that requested rate with an explicit channel count of one or two. The production `AVAudioFileSampleLoader` reads file/converter metadata, computes the selected converted channel-frame estimate with checked arithmetic, and rejects an over-budget request before allocating its PCM/conversion buffer; it then reads only the selected frame range and uses native sample-rate conversion. It rejects non-file URLs, missing/unreadable files, unsupported formats or channel counts, invalid source rates/frame counts, conversion failure, truncated output and nonfinite PCM. Every injected loader must honor the same preallocation budget contract. The protocol performs no asset selection, reversal, rate traversal, mixing or fallback.

`SampleLoadingError` has distinct `invalidFileURL`, `unreadableFile`, `unsupportedFormat`, `unsupportedChannelCount`, `invalidSampleRate`, `invalidFrameCount`, `conversionFailed`, `truncatedOutput` and `nonFinitePCM` cases carrying only the URL/value needed to diagnose the failure. LoopRenderer propagates that typed error; inconsistent compiled key/descriptor data is `LoopRenderingError.invalidSound`, invalid traversal state is `invalidEvent`, and distinct/aggregate cache excess has `sampleCacheLimitExceeded(limit:)`. No case is converted to silence or a procedural sample.

For each render, LoopRenderer owns a local cache keyed only by canonical URL, region and target rate; the changing remaining budget is request context and never part of cache identity. It loads only keys present in final compiled events, loads each distinct key once, and releases the cache when `render` returns or throws. Distinct cache entries may not exceed `PreparedLoop.maximumRows` (32), and the fixed aggregate budget is `requiredSampleRate * maximumDurationSeconds * maximumRows`, currently 22,579,200 Float channel frames (about 90 MB). This uses existing ceilings and is independent of the final audible extent, which may shrink only after decoded asset exhaustion is known. Before each miss the renderer subtracts the checked cached total and passes the remainder to the loader, then independently validates the returned actual channel-frame count and cumulative sum before insertion. Any key/URL mismatch, duplicate compiled descriptor identity, cache bound or integer overflow is a typed `LoopRenderingError`.

Traversal is region crop, native conversion, optional reverse, then pitch/rate traversal with linear interpolation. Mono duplicates to left/right; stereo preserves channels. At each frame the traversal increment is `samplePlaybackRate * targetFrequency / rootFrequency`, where `rootFrequency` is the selected asset root under A4=440 and `targetFrequency` applies the source `Tuning`, event pitch plus fractional offset, and instantaneous pitch-envelope semitones by the same formula as Synthesizer. Every reachable increment must be finite and positive; the source position is integrated continuously across a pitch envelope and seamless buffer fold. Procedural named samples lack an asset root and retain their P03.2 pitch-setting rejection.

Traversal begins at the asset-region boundary at each true event onset, continues through a seamless buffer fold without reset, and stops at the opposite selected-region boundary; it never loops or sustains a nonexistent sample. The audible event and `LoopEvent.durationBeats` end at the earlier of the configured gate/envelope horizon and the actual frame where traversal reaches that boundary. A sample ending before beat zero is nonwrapping; one crossing beat zero wraps only for the portion with decoded frames. Envelope/filter processing cannot extend silence past the asset boundary. Direct-file events select their sole URL; bank events require the compiler-provided key and never interpret the selection pattern. Envelope, filter, velocity, gain and pan use the existing per-voice order, and `samplePlaybackRate` intentionally changes pitch and asset consumption without changing the compiled musical gate or extent. Procedural named samples bypass `SampleLoading` and retain their current PCM behavior.

Swift Testing uses temporary AVAudioFile mono/stereo fixtures with distinguishable frames, rates and declared roots to prove direct selection, ordered-bank keys across finite/live cycles, one loader call per cache key, native conversion, crop/reverse/rate interpolation, event pitch/fractional offset/tuning/pitch-envelope traversal, stereo preservation, seamless traversal continuity, exact shortened event metadata and silence after exhaustion. It separately proves malformed/missing keys, URL/format/channel/rate/frame/nonfinite/conversion/cache failures, unsupported source-setting combinations, no procedural fallback and unchanged named-sample PCM. Voice release, stealing and choke remain P03.4.

P03.4 inserts one bounded offline voice scheduler before the existing per-voice renderer. A voice owns its traversal/oscillator phase, filter state, Envelope state, true onset/event order and current pre-mix stereo sample until its gate/release or decoded-asset boundary. Release and circular-fold portions count as active. Nil policy/choke dispatches directly to the existing overlap renderer and preserves its PCM byte for byte.

For finite sound, events are processed in start-frame then compiled-order order. For seamless sound, the scheduler begins empty one window before the rendered interval, processes that complete warm-up window without retaining its PCM, snapshots the normalized active/ramp state at beat zero, then processes the rendered window and snapshots the normalized state at its end. Both snapshots are taken at the identical phase immediately before admitting events whose onset maps to frame zero. Normalization identifies a voice by compiled event order, cycle-relative onset/age, DSP phase/filter/envelope state, last finite stereo sample and termination-ramp progress rather than its absolute virtual-cycle number. The render succeeds only when the two normalized boundary states are exactly equal; otherwise it throws `LoopRenderingError.nonPeriodicVoiceAllocation` and returns no PreparedLoop. This equality is the proof that repeating the returned buffer preserves allocation, oscillator/sample, envelope and filter state through the seam. A one-window horizon alone is not claimed to guarantee convergence, and the renderer never chooses an arbitrary history length or silently resets state at beat zero. End-exclusive horizons prevent a voice of exactly one window from surviving an additional recurrence.

Choke runs before source capacity at each incoming onset. A terminated voice receives a linear gain ramp over `min(128, remainingNaturalFrames)` of its otherwise natural future stereo samples, beginning at gain one and ending at zero; a one-frame remainder becomes zero immediately. The voice leaves allocation capacity at the decision instant, while its bounded ramp tail is mixed as termination cleanup and cannot be selected or terminated again. At most one such tail is created per compiled/virtual occurrence, so event and two-window bounds cap state and work. No collection allocation or file load occurs inside the per-frame voice loop.

Quietest selection uses `max(abs(left), abs(right))` from the actual finite pre-source-mix sample immediately preceding the incoming frame. At frame zero the seamless warm-up provides that sample; a finite voice without a previous frame uses its actual sample at the incoming frame before admission. Nonfinite candidate magnitude is a typed `LoopRenderingError.invalidEvent`, not a quietest winner. Ties use true onset then compiled order. Oldest and monophonic use the same tie order. The renderer keeps all original `LoopEvent` provenance metadata; scheduler decisions affect PCM only.

Swift Testing proves mono replacement, poly limits, oldest and actual-sample quietest choices with fixtures where velocity/age proxies choose differently, same-frame compiled-order ties, cross-source choke ordering, release-tail participation, decoded asset exhaustion, 128/short termination ramps and nil-policy byte identity. Seamless fixtures prove a matching normalized boundary state and sample-continuous repeated seam for a crossing voice with choke/steal, and a concrete history-propagating quietest case must fail as `nonPeriodicVoiceAllocation` instead of returning a nonperiodic buffer. Bounds/nonfinite failures and unchanged event/provenance arrays are asserted; one PreparedLoop reaches native playback with the scheduled PCM.

### P04 ordered offline effects and track mix

Code-declared `CompiledRenderNode.effect` is rendered into PreparedLoop PCM in dependency order; it never mutates the live AVAudioEngine master chain. EQ is the W3C peaking-EQ RBJ biquad. For finite input it starts at zero state and processes exactly the input node's owned horizon; its residual IIR state is deliberately discarded there, so EQ is a horizon-bounded tone shaper and does not claim or add an audible tail. Delay and reverb alone own P04 tail extension. Seamless EQ solves the two-state linear recurrence for the unique finite periodic state per channel and fails on a singular/nonfinite solution. Saturation is `x * (1 + drive) / (1 + drive * abs(x))`; distortion with positive drive is `clamp(x * (1 + drive), -1...1)`. Zero drive and zero wet dispatch to an exact input-copy branch. Every intermediate and coefficient is checked finite before Float conversion; final clamping remains at the existing renderer boundary.

Synchronized delay converts its exact MusicalTime through the render BPM. Its wet path has echoes at `time * (n + 1)` with gain `pow(feedback, n)` while that gain is at least `1e-5`; feedback zero therefore produces one echo. Reverb owns a deterministic finite stereo Schroeder impulse response: four parallel combs use base delays 29.7, 37.1, 41.1 and 43.7 ms scaled by `0.5 + roomSize`, feedback `0.2 + 0.75 * roomSize`; two serial all-pass stages use 5.0 and 1.7 ms under the same scale with feedback 0.5. The impulse response is cut at `0.1 + 2.9 * roomSize` seconds and right-channel delays are each one frame longer for deterministic decorrelation. Dry/wet is `dry * (1 - wet) + processedWet * wet`; no factory preset guesses continuous roomSize.

Delay and reverb convolution use one render-owned `FFTConvolver` serially across graph nodes. Delay materializes its already bounded finite impulse at the rounded declared tap frames and uses the same convolution path; it does not execute a nested tap-by-input-frame loop. For finite output convolution is linear; for seamless output it computes the same linear result and folds every result index modulo the exact loop frame count. Transform length is the checked next power of two covering `inputFrameCount + impulseFrameCount - 1`, at most 2,097,152: this is the derived ceiling for a 44.1 kHz seamless 16-second input convolved with the longest accepted 16-second delay impulse. Each serial convolution call owns at most six transform-length Float arrays; those arrays are released before the next graph-node convolution. Forward/inverse FFT setup pairs are cached by transform length in the render-owned convolver and its sole `deinit` releases every cached pair on normal return or unwinding; failure to create the inverse setup releases the just-created forward setup immediately. Six arrays occupy at most 48 MiB at that maximum transform length, apart from the separately bounded node and impulse buffers. Requested lengths and workspace-budget arithmetic are validated before Swift array construction. Failure to create a native Accelerate setup is typed; ordinary Swift array allocation follows Swift runtime out-of-memory behavior and is not claimed recoverable. No custom allocator or time-domain fallback is introduced.

Graph horizon analysis runs before node-buffer allocation. A source node ends at its last audible baseline voice frame under the existing gate, envelope and asset-exhaustion rules; a mix node ends at the maximum child horizon. Effect output never feeds a longer horizon back into source voice generation, so delay or reverb extension cannot prolong an existing gate or asset. Finite delay/reverb chains extend only their input subtree through the last declared echo/impulse frame, then the renderer keeps at least the original compiled whole-bar window, pads a longer result to a whole bar and enforces the existing 32-beat, 16-second, node and memory bounds. Delay derives its qualifying echo count without allocating a tap list; if the last echo whose gain is at least `1e-5` exceeds the 16-second frame ceiling, analysis fails with a typed bound error before effect allocation. Seamless delay/reverb fold every qualifying finite tap modulo the canonical window, which is exact circular convolution and creates no hidden tail state; EQ uses its verified periodic state and stateless shapers need none. A zero-wet node adds no horizon. Unsupported filter/compressor/chorus/send/output remains a typed failure with the previous loop retained.

`CompiledRenderNode.track` renders its input once, then applies level, optional equal-power pan and mute/solo gate. Before allocating node buffers, LoopRenderer derives the source-audible and transit-enabled sets once from immutable `CompiledTrack.id`, `parentID`, `isSoloed` and `isMuted` metadata. When solo is active, source buffers are admitted only for events whose innermost `trackID` is soloed or descends from a soloed Track; untracked and ancestor-owned direct sources are zeroed. Ancestor track nodes remain transit-enabled only to carry admitted descendant buffers, while unrelated nodes are zeroed; mute at any enabled node still blocks its subtree. Missing IDs, cycles, a source with conflicting owning track IDs, or a node/metadata mismatch are typed invalid-graph failures. Default track settings use an exact input-copy branch. Empty metadata-only tracks have nil `renderNodeID` and no node. Track processing composes with surrounding render nodes in array dependency order and does not alter LoopEvent, row provenance, source identity or recurrence. Per-node buffers are released after their final consumer and remain under the existing frame/node work budget.

Swift Testing compares EQ impulse output with RBJ reference values; saturation/distortion formulas and neutral branches sample by sample; delay tap frames/gains at multiple BPMs; reverb determinism, room-size duration, stereo decorrelation and wet mix; chained order and finite horizon rejection; circular convolution and EQ seam state. Track fixtures prove nested solo source ownership versus ancestor transit, mute precedence, level/pan order and unchanged events; specifically, soloing an inner E4 Track passes E4 through its outer node while silencing a C4 source owned directly by that ancestor and an unrelated G4 Track. One ordered chain reaches native playback; invalid/nonfinite/singular/bound failures return no PreparedLoop.

Swift Testing fixtures compare actual PCM and frequency/filter/envelope measurements, decode temporary mono/stereo files through the production loader, exercise every failure and cache bound, and prove voice stealing/choke order. Integration submits a rendered loop to the native engine and observes nonzero output while evaluation failure retains the previous revision.

### P05 continuous automation

LoopRenderer evaluates compiled P05.1 signals without parsing source or changing event provenance. Finite transport phase is the absolute output-frame time converted to beats at the render BPM, and finite Hz phase uses `frame / sampleRate`. In seamless mode, synchronized signals use the canonical discrete coordinate `frame / frameCount * sourceBeatCount`, so the integer PCM window represents exactly its compiled beat period even when `ceil(beatCount * 60 / BPM * sampleRate)` adds a fractional nominal frame. Seamless Hz signals remain physical-time signals using `frame / sampleRate`, and validation requires `frequency * frameCount / sampleRate` to be an integral cycle count. Both coordinates continue into the next repeated buffer by their complete cycle count; neither resets an unresolved phase at wrap. Source pitch/cutoff automation is evaluated inside each active voice before oscillator/sample traversal and RBJ coefficient generation. Gain/pan automation render nodes evaluate once per output frame over their complete input horizon, then apply the existing gain multiplication or equal-power pan law in dependency order. Signal/range arithmetic remains Double through validation and converts to Float only after a finite representable result. The nil-automation branch retains the prior renderer path exactly.

Before PCM allocation, validation uses reduced `MusicalTime` numerator/denominator arithmetic to require every final retained synchronized signal period to divide the compiler's seamless window exactly and independently of event fast/slow transforms; only physical Hz cycle integrality is checked in Double frame time. It also verifies both effective pitch endpoints, both cutoff endpoints against 22,050 Hz, graph references and descriptor/point bounds. No signal may reset at an event or loop seam. An automation node whose graph input includes a finite effect tail continues the same transport/seconds clock across that tail rather than restarting at the dry horizon; automation placed inside an effect is already part of that effect's input and does not retroactively modulate its generated tail. Automation itself adds no tail. Typed failure returns no PreparedLoop, so evaluation retains the prior adopted revision. Swift Testing differentially measures every signal and mapped target at exact frame/beat boundaries, crossing voices and effect tails, plus seamless first/last-period continuity and existing PCM identity when absent.

### P05 named buses

LoopRenderer consumes only compiler-resolved dependency-ordered send, trackSend and busReturn nodes. A send renders its input once, returns that dry buffer unchanged and contributes a checked scaled view to its named return accumulator; a return sums contributions in compiled declaration order and is then processed by its downstream nodes. Track sends consult immutable Track ancestry: pre-fader excludes the owning Track level/pan and post-fader includes them, while both suppress contributions when the owner is solo-ineligible, muted or under a muted ancestor. Generic Sound send uses only its explicit declaration position. Routing never changes LoopEvent/LoopRow metadata or source peak provenance.

Before rendering, graph liveness and consumer counts prove that no node is read after release and at most 32 complete stereo buffers are simultaneously owned. Each node is materialized once, shared consumers borrow it synchronously, and storage is released after the final consumer; no bus mutation occurs on the AVAudioSourceNode callback. Unrouted roots and terminal `output("main")` sinks sum into PreparedLoop stereo output. An unmatched legacy send, unresolved graph invariant, duplicate contribution identity, non-main external output, nonfinite sum or live-buffer bound fails before a successful loop. Finite bus effects use their declared horizons; seamless sends/returns preserve the same canonical window and circular effect contracts.

### P05 dynamics and event ducking

LoopRenderer owns the concrete P05.3 DSP defined by the [SoundComposition dynamics contract](../../../../Sources/SwiftMusic/SoundComposition/DESIGN.md#dynamics-and-event-ducking). A resolved event-duck node reads compiled trigger onsets and scales its named return at that return boundary; a resolved sidechain effect reads its detector buffer without consuming or altering it and scales only its signal input. Self compressor, gate and limiter use their input as detector. Dependency/liveness accounting treats a sidechain as a second synchronous borrower, keeps each buffer through its final consumer and includes dynamics nodes in the existing 32-live-buffer proof.

The renderer computes linked stereo peak detection, dB transfer and gain smoothing in Double, validates every coefficient/state/sample, and converts only the final scaled sample to Float. Dynamics do not extend node horizons. Finite state starts from the descriptor's neutral state. Seamless state uses the bounded 64-pass periodic-state solver and rejects an unverified residual before returning PCM; event duck envelopes fold directly across the canonical frame window. There is no time-domain reset, detector fallback, channel-unlinked path or AVAudioEngine master substitution. `EffectProcessor` removes the incomplete marker for compressor only when legacy and explicit compressor, gate, limiter, sidechain and duck success/failure fixtures pass; chorus remains separately unsupported.

Swift Testing compares reference transfer values and frame-exact attack/release, proves external BusReturn detection, dry preservation, return-boundary duck order, overlap depth, limiter ceiling, gate state, seamless boundary equality/failure, horizon identity, liveness limits and unchanged LoopEvent/LoopRow metadata. A real evaluated named-bus arrangement renders nonzero ducked/dynamics PCM and reaches AudioLoopEngine; invalid routing, state or PCM returns no PreparedLoop so the adopted loop remains unchanged.

### P05 harmony and portamento

LoopRenderer consumes compiler-final harmony group/occurrence metadata, legato gates and `portamentoStartMIDINote`; it never infers chord membership, copied occurrence or a predecessor from sorted PCM events. Portamento is evaluated in `RenderedVoice` before existing pitch automation, pitch envelope and tuning. The oscillator frequency path and `PreparedSampleVoice.increment` use the same semitone interpolation at every frame, and sample horizon calculation advances through that identical function so a glide cannot read beyond decoded storage. Seconds duration is transport-independent; beats duration uses the render BPM. A glide reaches and holds its destination when its duration ends, including across a seamless buffer boundary, without resetting phase or sample position.

Synthesizer and rooted file/bank sources support the path under existing Nyquist, sample-cache and voice-horizon bounds. Procedural samples and white noise reject portamento as an unsupported pitched-source setting. Nil metadata dispatches to the prior arithmetic exactly. Native Swift Testing measures start/mid/end pitch for oscillator and temporary rooted sample, seconds versus beat timing, live-wrap continuity, pitch automation/envelope composition, sample exhaustion and typed capability/range failures. Compiler-to-renderer fixtures retain row/token/track/duck metadata and one real evaluated harmony loop reaches AudioLoopEngine.

### P05 modulation effects and post-mix filter

LoopRenderer implements the [SoundComposition P05.6 contract](../../../../Sources/SwiftMusic/SoundComposition/DESIGN.md#modulation-effects-and-post-mix-filter) in dependency order. Static post-mix filter reuses the RBJ/filter state owner; chorus and flanger use bounded per-channel fractional delay lines; phaser owns at most 32 first-order all-pass states per channel; stereo width is a stateless mid/side matrix. Tremolo arrives through the existing gain-automation node and vibrato through the existing per-source pitch-automation path, so the renderer adds no duplicate modulation descriptor or clock.

Effect horizon analysis includes only the declared chorus/flanger delayed tail and rejects it before PCM allocation when it exceeds the 16-second ceiling. Seamless Hz validation uses physical integer cycles. Circular chorus reads directly; flanger/phaser accept only a finite verified periodic state within the 64-window/residual bound. Filter uses its established periodic solver. The exact neutral branches do not allocate delay/state buffers or replace earlier source automation. Every intermediate remains finite, node/live-buffer/modulation-state bounds are enforced off callback, and a failure returns no PreparedLoop.

Swift Testing measures filter frequency response, modulation phase and delay interpolation, feedback/tail bounds, phaser stages, stereo-width matrix, neutral byte identity, graph order and finite/seamless state. Existing automation tests own tremolo/vibrato signal evaluation; P05.6 adds audible oscillator/rooted-sample and declaration-order fixtures plus one real evaluator-to-AudioLoopEngine chain with prior-loop retention on failure.

### P05 retained rerender session

`LoopRenderSession` is the worker-owned rendering boundary for P05.7. Its throwing initializer accepts one immutable CompiledSound, BPM, meter and SampleLoading dependency, validates the ordinary LoopRenderer bounds, prepares every referenced decoded sample once under the existing 32-entry/22,579,200-channel-frame budget, and produces an immutable control catalog. `render(overrides:)` validates the complete active override set against that catalog, reuses only the immutable sample preparation, and executes the same LoopRenderer graph/DSP path with a render-scoped overlay view over the untouched baseline. It does not call user code, mutate or copy the baseline graph, invert prior PCM, retain stems or change event/source/node topology.

Control addresses and values follow the Playback contract. The overlay lookup may replace source live gain/pan/pitch/cutoff evaluation, a gain/pan node's scalar or automation output, or Track level/pan, but it cannot add/remove/reorder a source, event, Track, render node, root, bus or effect. ### P06 decoded-sample processing

LoopRenderer applies an event `SampleSlice` inside the already selected source region before reverse/rate/pitch traversal. A chopped event begins at its own slice boundary and never reads an adjacent slice; asset exhaustion, Envelope, filter, voice policy and circular wrapping retain their existing owners. Count-one dispatches to the prior decoded traversal byte for byte.

Pitch-preserving stretch and granular playback have separate owners. `NativeSampleTimeStretcher` uses a private AVAudioEngine in manual offline mode with AVAudioPlayerNode -> AVAudioUnitTimePitch, pitch zero and `rate = selectedInputFrames / targetFrames`. Target frames use the renderer's checked BPM/sample-rate frame conversion for the exact `sampleStretchDuration`; rate must remain within the same native 1/32...32 capability already used by Playback. It renders serially off the audio callback, requires finite nonnegative reported latency, renders latency plus target support, discards the checked latency prefix and returns exactly targetFrames finite interleaved frames. Setup, scheduling, manual-render status, insufficient output, invalid latency/rate and nonfinite PCM are typed failures. The Playback TimePitch remains a distinct master transport owner and is never reconfigured by sample preprocessing.

Stretch preprocessing runs on the already selected event slice before reverse and ordinary traversal. Its cache key is decoded asset identity, effective slice and targetFrames; pitch/tuning/portamento are excluded because the stretched PCM remains at the asset root. At most 32 processed entries and the existing 22,579,200 channel-frame aggregate are retained; combined decoded plus processed storage is therefore explicitly bounded by twice that existing aggregate, with the processed budget checked before native buffer allocation. `LoopRenderSession` may retain both immutable caches across P05.7 rerenders. A production native fixture must demonstrate the declared target duration and retain a 440 Hz input's dominant frequency at 440 Hz within the measurement tolerance; a shifted spectrum such as the rejected Hann-only overlap-add result is a contract failure.

`GranularSampleVoice` is the separate optional timbral-grain owner, constructed over the stretched PCM when stretch exists and otherwise over the selected decoded slice. Its base launch position follows ordinary traversal time. Grain reads use the same instantaneous root-pitch/tuning/event-offset/pitch-envelope/portamento increment as ordinary sample playback. `samplePlaybackRate` remains the intentional pitch/rate traversal multiplier after preprocessing. No granular configuration is implied by `sampleStretch`, and granular output has no pitch-preservation guarantee beyond applying the declared pitched read increment.

Each grain uses a Hann window and linear sample interpolation. Hop is `grainFrames * (1 - overlap)` with checked Double-to-frame conversion and must resolve to at least one frame. A private renderer `GranularDeterministicRandom` maps descriptor seed, source ID, canonical event order and grain ordinal to a deterministic signed launch offset bounded by `positionJitter * grainFrames`. It implements the fixed SplitMix64 transition/constants already documented by SwiftMusic, but owns its state and identity locally because SwiftMusic's rhythm random function is private and represents a different event-transform responsibility; P06 exposes no public generic random API. Reads outside the selected slice contribute zero; normalization divides by the accumulated finite window weight, with zero weight producing silence. Finite mode starts with no prior grains and ends at the existing voice horizon. Seamless mode includes grain launch ordinal, scan/read positions and active window/weight state in the existing `RenderedVoice.State`; `VoiceScheduler` uses its established prior-period warmup and exact start/end state comparison. An unmatched state is the existing typed nonperiodic-voice failure, and beat zero never restarts a grain.

Before allocating grain state, the renderer checks grain/frame arithmetic, at most 4,096 launched grains per voice, at most 4,096 retained grain-ring slots summed across every prepared voice template, and at most 1,048,576 total grain launches including seamless warmup occurrences. The retained-slot bound conservatively includes inactive ring capacity and therefore also bounds simultaneously active grains; admission never depends on a later activity sweep. These are P06 DSP work/state ceilings in addition to existing event, sample-cache, frame and 16-second limits. Grain state is allocated off callback and reused through the voice. Hann weights are computed scalarly per frame, so no window array or per-frame collection allocation exists. Invalid frame conversion, count, nonfinite position/sample/weight, unsupported source, resource excess or unverified seamless state is a typed rendering failure with no ordinary-playback fallback.

### P06 oscillator and synthesis rendering

`OscillatorPreparation` validates one CompiledSource before voice allocation and owns immutable wavetable mip levels; `RenderedVoice.State` owns per-unison carrier/modulator phases and colored-noise FIR history. Existing sine, square, saw, triangle and legacy white-noise cases dispatch to their prior arithmetic byte for byte when no new setting applies. New band-limited saw and pulse use the standard two-sample polyBLEP correction at each discontinuity with `dt = frequency / sampleRate`; a pulse at width 0.5 is the new band-limited square choice without changing legacy `.square` PCM.

FM advances one carrier and one modulator phase per unison lane and emits `sin(2*pi*carrierPhase + index*sin(2*pi*modulatorPhase))`, with modulator increment `carrierFrequency * ratio / sampleRate`. Validation requires the reachable absolute instantaneous-frequency bound `carrierFrequency * (1 + ratio * index)` to be finite and below Nyquist; it is a stability/admission bound rather than a claim that phase modulation has finite spectral support. Pulse width is static per source. Every oscillator uses the same positive carrier frequency produced by portamento, pitch automation/envelope and tuning before adding its unison cent offset.

`WavetablePreparation` owns its scoped Accelerate DFT setup and builds checked fixed-length octave mip levels from the immutable cycle. Every level contains the original `N` samples: the first retains bins through the source Nyquist cutoff `N / 2`, and each following level halves that harmonic cutoff until the final cutoff of one. No level removes the fundamental or shrinks the table, including the valid two-sample cycle. At each frame the renderer selects the highest-detail level whose retained harmonics remain below output Nyquist and linearly interpolates cyclic samples; this is bounded approximate anti-aliasing rather than a zero-alias guarantee. Level changes crossfade over 32 frames to avoid a step, with level/fade state included in `RenderedVoice.State`. A source owns at most 12 levels and 49,152 Float values (`4,096 * 12`), and all sources together own at most 262,144 prepared Float values. Setup/size/arithmetic/nonfinite failure is typed before voice allocation; there is no raw-table or sine fallback.

Typed noise is counter-seeded and deterministic per source/event/frame. White maps one SplitMix64 sample directly. Pink uses a 256-tap finite fractional integrator: `h[0] = 1`, `h[k] = h[k - 1] * (k - 0.5) / k`, normalized by the positive coefficient sum. Brown uses the bounded leaky integrator `y[n] = p * y[n - 1] + (1 - p) * white[n]`, where `p = exp(-2 * pi * 20 / sampleRate)`; the `(1 - p)` gain keeps a bounded white input bounded. At 44.1 kHz, a log-frequency least-squares response measurement over 200...4,000 Hz must distinguish the colors: the specified pink kernel measures approximately -3.10 dB/octave and brown approximately -6.00 dB/octave. Finite voices use zero history before true onset. Seamless voices derive pink history from canonical prior-frame hashes, warm brown state across prior periods, and include all colored-noise history in the existing normalized `RenderedVoice.State` boundary comparison, so an accepted buffer repeats without a state reset.

Unison allocates exactly its declared phase/state lanes before rendering and averages lane PCM before source filtering/Envelope and event gain/pan. Across every prepared voice template, total oscillator lanes may not exceed 4,096; wavetable storage uses the separate bound above. No per-frame collection allocation occurs. Nonfinite phase/state/sample, invalid effective/FM frequency, resource excess or unmatched seamless boundary is a typed rendering failure. The current `FIXME(INCOMPLETE_IMPLEMENTATION)` preceding unison rejection is removed only when this complete dispatch and its typed incompatible-source cases are verified.

Swift Testing measures every legacy oscillator's compatibility, new polyBLEP alias-energy reduction against the naive discontinuous reference, pulse duty cycle, FM carrier/modulator peaks and range rejection, unison lane frequencies/mean/one-lane identity, deterministic white/pink/brown seed and spectral-slope bands, wavetable cyclic interpolation/mip alias suppression/level crossfade, pitch and portamento composition, finite onset state, seamless exact boundary state and all preparation bounds. One real evaluated Session drives each synthesis family through existing effects and AudioLoopEngine; invalid synthesis retains the previous adopted loop.

### P06.3 MIDI event projection

`LoopEvent` retains its existing display `midiNote` and adds Codable `midiProjection: MIDIEventProjection`. The projection is `.none` for an unpitched event, `.note(Int)` for a final stable integral MIDI pitch in 0...127, or `.unsupported(MIDIProjectionLimitation)` with `.fractionalPitch`, `.outOfRange`, `.timeVaryingPitch` or `.legacyMetadataMissing`. A stable integral result outside 0...127 is `.outOfRange`, even when source tuning keeps the native oscillator frequency valid. Legacy decoding maps an absent projection to `.none` when `midiNote` is nil and otherwise to `.unsupported(.legacyMetadataMissing)`; it never silently exports a pre-P06 base pitch.

LoopRenderer is the sole projection owner because it already resolves the final audible pitch path. Integer static/pattern transpose, scale/chord/arpeggio and any constant pitch descriptor contribute to `.note`. A nonintegral final pitch produces `.fractionalPitch`. Any pitch automation, envelope, portamento or vibrato that changes effective MIDI during the audible event produces `.timeVaryingPitch`; a mathematically neutral/constant descriptor may still produce `.note`. Tuning, unison, FM and `samplePlaybackRate` are instrument/timbre traversal settings rather than score-note transforms, so they do not change the projected note or create extra MIDI lanes. White/colored-noise synthesizers and procedural named samples are `.none` despite any display-only middle-C metadata; rooted file/bank samples remain pitched score events. Projection generation changes no PCM, display pitch, event timing, provenance, ordering or row metadata. Tests cover C4 plus integer +12 as note 72, fractional and out-of-range harmony, varying and neutral pitch paths, instrument-setting exclusion, noise/procedural `.none`, rooted samples and legacy decode. Core MIDI consumes this result without interpreting SwiftMusic declarations.

### Finite and live-loop rendering

`PreparedLoop.maximumBeatCount` owns the existing 32-beat preparation limit shared by validation, rendering and the evaluator compiler policy. LoopRenderer does not interpret recurrence or copy compiled events. MusicPlaygournd evaluation requests `SoundCompiler.compile(_:liveLoop:)` with the current quarter-note bar and a maximum beat horizon derived from the existing 32-beat and 16-second preparation limits, then passes the fully expanded CompiledSound to the existing renderer API. Other clients using finite `compile(_:)` and the same renderer retain their prior behavior.

The live CompiledSound extent is already a checked whole-bar common window, and every event already contains its final onset-sampled gain, pan, pitch and provenance. LoopRenderer validates that extent under its existing beat/duration/event limits and renders it once. AudioLoopEngine repeats the finished common window, so independent track and numeric-pattern phases survive wrap without renderer-owned musical semantics.

A seamless compiled extent must already align with the renderer's requested meter; a mismatched meter fails before PCM allocation rather than rounding and changing the recurrence window. For `.finite`, LoopRenderer retains its existing end-of-window clipping and edge-fade behavior. For `.seamlessLoop`, an event whose full gated duration crosses `beatCount` is folded into two segments in the same PCM buffer: onset through the window end and beat zero through the true release. Oscillator/sample elapsed time and envelope phase continue across the split; the split adds no attack, release or edge fade. The existing attack fade occurs only at the true onset and the release fade only at the true end. Per-source peak PCM uses the same folded signal. A crossing duration greater than the window or invalid folded frame arithmetic is a typed rendering failure, never a clipped success.

`LoopEvent.durationBeats` retains the full audible duration and `wrapsLoopBoundary` records that its active interval is circular; legacy decoding defaults the flag to false. PreparedLoop validation requires `0 <= startBeat < beatCount`, positive finite duration, and either a nonwrapping end within the window or a wrapping end beyond it with duration no greater than `beatCount`. Rhythm, timeline and inline views draw the two visible segments of a wrapped event. Transport/token activity uses the same circular interval (`beat >= start` or `beat < end - beatCount`) and one `sourceID`/`patternStepIndex`, so the literal remains active through beat zero without a phantom second token.
