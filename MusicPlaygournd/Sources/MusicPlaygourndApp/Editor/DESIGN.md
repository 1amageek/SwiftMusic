# Editor

## Purpose and Scope
Component. Parent: [App](../DESIGN.md). Children: none.

## Responsibilities and Boundaries
MainActor session model owns editable source, revision allocation, evaluation task, diagnostics, open/save and UI state.

## Related Designs
Use the parent/child links above. Dependencies: SwiftMusic owns event semantics; Core owns rendering/playback/evaluation contracts; App consumes Core.

## Architecture
```text
edit -> invalidate pending -> debounce -> evaluate -> submit -> snapshot -> rhythm Canvas
dot/word or Control-Space -> semantic request -> AppKit popover completion panel -> validated source edit
latest evaluation/completion status -> bottom Logs disclosure -> optional source reveal
compact header: file identity + transport/BPM/meter + Controls -> bounded native popover
header miniature waveform/spectrum -> playback snapshot; monitor popover -> detailed telemetry
body -> code and inline results
adopted control catalog -> complete override generation -> retained worker rerender -> same-revision crossfade
```

## Contracts and Invariants
The editor owns inline, side, and bottom result layouts; inline is the default. Native NSTextView layout remains the authority for compiler-captured source lines. Pattern anchors own token glow and side-timeline alignment, while compiler-derived result lines own inline placement after the complete sound expression. Each result shows actual pre-mix PCM peaks, compiled event timing, and the adopted transport cursor. The header monitor shows actual post-FX stereo waveform and spectrum from the playback tap. No independent musical or Swift parser and no per-row transport exists.

### Inline results

Inline rhythm/note results are read-only child views of the NSTextView document view, so code and results share one native vertical and horizontal scroll coordinate space. For each adopted row, `LoopRow.resultLine` is the end line of the outermost explicit Swift call expression containing its compiler pattern anchor; the card is placed after that result line, below all chained modifiers. `NSLayoutManagerDelegate` reserves paragraph spacing there without inserting characters or mutating text-storage attributes. Sources with the same result line share one contiguous bounded region and stack deterministically. Each card uses horizontal beat time and a moving transport cursor. Note events use vertical MIDI pitch lanes with higher pitches above lower pitches; non-pitched rhythm events use a named source lane. Event start and audible duration come from the adopted LoopEvent, while the existing pre-mix peaks may remain a secondary signal trace rather than replace the event grid. Rows without a current result-line mapping are omitted from inline placement and remain represented by the existing alternate views.

A `LoopEvent` marked `wrapsLoopBoundary` is one musical event and one lexical token. Inline, side and bottom visualizations split only its geometry at the right/left window edges. Playback highlighting evaluates its circular active interval, keeping the original token active across beat zero; it does not synthesize a beat-zero onset, token or source association.

Changing layout, adopting a loop, moving the transport, or relaying out cards must preserve the exact source string, UTF-16 offsets, glyph-to-character mapping, selection, undo stack, completion snapshot/ranges, and syntax/token temporary attributes. Cards never intercept editing or synthesize source content. An invalid or stale edit keeps the adopted revision's cards and PCM visible, with both pattern and result anchors transformed by the current SourceLineMap. Inline, side, and bottom use the same adopted PreparedLoop and beat position; the layout control only changes presentation. Side coordinates are converted through the native editor-to-clip-view transform rather than reconstructed from scroll offsets.

A source map belongs to its submitted revision and becomes visible only when that revision is adopted. Exact text edits shift untouched anchors; deletion of an anchor removes its association until successful evaluation. Unmapped sources are counted explicitly. Failed edits preserve adopted audio and wave data. The UI distinguishes playing and edited revisions. Typed compiler diagnostics select their exact UTF-16 source range. Open/save uses UTF-8 .swift and preserves edits on canceled panels.

### Session file sidebar

The Editor component owns a collapsible native left file sidebar beneath the shared transport header. It lists direct child folders and regular Swift source files of one user-selected local directory, with folder navigation, parent navigation and explicit refresh. NSOpenPanel selects the directory. The sidebar owns browser location and listing state; SessionModel remains the sole document/source/dirty-state and playback authority. A sidebar toggle restores the full editor width without replacing CodeEditor. The current document and its unsaved indicator derive from SessionModel, not a second document model. This increment has no recursive tree scan, watchers, rename or delete operations.

Directory enumeration skips descendants and admits at most 4,096 direct entries before display filtering or sorting; the first excess entry produces a typed too-many-entries failure rather than a partial success. Directory listing, metadata and creation errors are typed and shown explicitly. A failed refresh retains the previous listing with a visible stale/error state and never changes the current document. Symlinks are omitted so navigation operates on actual directories and regular files only; explicit parent navigation may leave the initially selected directory because this browser is not a sandbox boundary.

Selecting a Swift file uses the document-tab open path defined below; the existing throwing read/UTF-8 validation remains the admission boundary before selecting a new buffer. An open failure preserves the current source, URL and audio through that existing failure path. Choosing a folder or refreshing never evaluates code.

New Session uses NSSavePanel with a Swift filename and the current browser directory, the existing `SessionModel.initialSource` template, and an exclusive no-overwrite write. Creation does not discard another open tab; panel cancellation creates nothing. Existing destinations are rejected even if the save panel offers replacement. A successfully created file opens through the same document path and refreshes the listing. If creation succeeds but opening fails, report that the file exists while retaining the prior document; do not delete a successfully written user file or claim document adoption.

Focused Swift Testing uses temporary directories to prove direct-only listing, filtering, limit rejection, explicit filesystem failure, template creation and collision preserving existing bytes. Existing document tests remain the authority for adoption/dirty-state behavior. Filesystem completion evidence composes the existing four real-filesystem browser tests (listing/navigation/refresh, bounds, failures, template creation/collision), reviewed production NSOpenPanel/NSSavePanel routing, and the production ContentView hosted in NSHostingView for two-file open/edit/switch/undo/save/close-cancellation. The separate Release app proves sidebar toggling and retained playback. Successful interactive folder-choice or new-file panels are not required additional gates: those attempts were interrupted by user interaction and are not reported as observed successes. The sidebar fits beside the existing minimum code width; hiding it restores that width. Core and SwiftMusic contracts do not change.

### Document tabs and active playback

SessionModel owns one bounded collection of open document buffers with stable IDs, standardized local URL identity, source and dirty state. Its existing `source`, `fileURL` and `hasUnsavedChanges` surface refers to the active buffer so evaluation and save callers retain one authority. Opening an already-open URL selects that buffer without rereading or replacing unsaved edits. Opening another file reads and validates it before adding/selecting it. Switching tabs preserves dirty buffers without a discard prompt. The earlier single-document sidebar discard rule is superseded for tab opening and switching; Save/Cancel/Discard applies when closing a dirty tab or terminating the workspace.

Each open buffer owns independent native UndoManager, selection and horizontal/vertical scroll state. CodeEditor retains one visible NSTextView and exchanges those states at a document-identity boundary, ending the prior edit group and canceling completion before replacing text without registering an undo edit. Undo in one tab must never edit another tab. Deferred completion/layout callbacks are admitted only for their originating document ID; the same text in two tabs is not sufficient identity. Closing releases that tab's undo and editor state. The initial untitled buffer remains a real tab. When the last tab closes, create a fresh clean untitled template so the existing editor always has an active buffer. The collection is bounded to 32 documents (each source is admitted at 64 KiB), verified at the exact boundary; reaching it rejects the new open without dropping an existing buffer.

There is one SessionModel, evaluator and audio engine for all tabs. Tab activation follows the existing document-change abort/reset and immediate-evaluation path with globally monotonic revisions. The previous adopted audio continues until the selected buffer successfully adopts; failure keeps that audio and reports the selected buffer's error. Inactive tabs do not independently evaluate or produce audio. Adopted audio retains its originating document ID: source-anchored cards, token glow, diagnostic reveal and completion from one document never attach to another, even if text or line numbers match. Header/status distinguishes the active edit from another tab's still-playing revision. Existing host-settings, Performance cleanup and adoption contracts remain the authority on a successful document transition.

Save acts on the selected buffer, preserving each other tab's dirty state. Save As updates identity only after successful writes and rejects a destination already owned by another open tab. Closing an inactive dirty tab prompts for that buffer without selecting/evaluating it as a side effect. Cancellation or failed save prevents removal. Window close and application termination check every dirty tab; cancellation anywhere keeps the workspace and remaining dirty buffers open, while already completed saves remain saved. ApplicationDelegate invokes the all-document guard rather than the former active-only guard.

Focused model/AppKit tests prove two dirty buffers survive switching, duplicate URLs select rather than reload, per-tab undo/selection/scroll remain isolated, close and termination cancellation retain unsaved buffers, and stale same-text completion cannot cross tabs. The existing production NSHostingView workflow proves two-file open/edit/switch/undo/save/close-cancellation in the Debug AppKit environment; it is not labeled Release-panel evidence. Failed-edit audio retention is established compositionally by prior native transport behavior, the actual packaged-SDK worker retaining adopted revision 3 and nonzero PCM after an invalid candidate, and reviewed SessionModel document/revision gating. These local guarantees replace a further disruptive interactive file-panel workflow without claiming that workflow was observed. Header proof verifies global-only content, neutral toggle, functional tabs, master-only XY changes and actual compact output monitoring. The file browser's direct-entry bound includes hidden entries before display filtering, and every listing/metadata/create failure is wrapped in its typed filesystem failure contract.

### Logs pane

ContentView presents one dedicated `Logs` disclosure below the editor body and above the status bar. It is collapsed by default and preserves the user's explicit expanded/collapsed choice for the current view lifetime. The collapsed label always exposes the current error count; the expanded content shows the latest evaluation diagnostic and latest completion status from SessionModel, and enables source reveal only for an exact typed diagnostic range; raw compiler logs remain readable without a guessed location. Moving this presentation out of the editor must keep the CodeEditor view identity, source, selection, undo stack, completion state, adopted revision, playback, and visualization unchanged. Logs owns presentation only: it does not collect history, create a logging backend, or reinterpret diagnostics.

TimelineTextView requests semantic completion automatically after a dot or identifier typing pause and manually with Control-Space. An AppKit popover and table present signature-bearing labels while keyboard focus remains in the editor. Up/Down only move selection; Return/Tab explicitly accept and Escape dismisses without mutation. Results are cached only for the exact source snapshot, UTF-16 cursor, and request generation. Final acceptance applies the candidate replacement once through validated NSTextView editing, creates one undoable source edit, and selects the first snippet argument when present. Any intervening edit, selection move, cancellation, or completion failure dismisses the result without changing source, revision, anchors, diagnostics, or adopted playback. Full IDE navigation, refactoring, formatting, and keyword-only fallback are outside this component. The custom presentation is required because native `NSTextView.complete` commits preview selection on candidate navigation.

Dense native controls use 8/13/21 spacing and mint/cyan on dark surfaces. Native line metrics override spacing tokens for exact alignment. Wave amplitude and spectrum height encode actual signal values, not decorative animation. Text labels and accessibility descriptions accompany color.

### P05 live-control session

SessionModel owns the MainActor composition of retained evaluation, transport adoption and control UI state. Each source evaluation calls `evaluateRetained` with its allocated revision, stores the returned candidate catalog and line map, and submits only its initial loop to AudioLoopEngine. A candidate remains owned by SourceEvaluator while that exact revision is pending in transport. Cancellation or a newer edit may discard a candidate only after `beginUpdate` has invalidated the same pending engine revision; it may never leave a submit-capable pending loop whose worker has already been destroyed.

`refresh()` observes revision and override generation. When transport first reports a candidate revision as adopted, SessionModel awaits `evaluator.adopt(revision:)`; source/node/Track controls remain unavailable during this handshake. Only a true result followed by `controlsAvailable(revision:) == true` publishes that catalog and enables its addresses. False keeps adopted PCM, states that controls are unavailable for that revision, and sends no request to a missing worker. After an ordinary override error SessionModel queries the same typed lifecycle state: true preserves enabled controls and reports only that request failure, while false disables compiled controls after a fatal worker fault. It never classifies failure by parsing diagnostic text. Promotion retires the prior worker only through SourceEvaluator's lifecycle contract. An adoption task publishes only while the engine snapshot still reports that adopted revision and the task remains current; a newer failed or pending edit revision does not disable the still-adopted revision's controls.

While compiled controls are enabled, SessionModel starts at most one MainActor health-check Task and polls `controlsAvailable` no more than once per second. This bounded UI observation detects a passive worker exit without waiting for a gesture; false disables compiled controls, preserves PCM and publishes one diagnostic. The poll performs no work on the audio callback, never changes source/edit revision and is canceled and awaited during model shutdown. One second is the app's observation cadence, not a worker liveness timeout or audio guarantee.

Source/node/Track gesture state is a dictionary keyed by the complete adopted `LiveControlAddress`. Each accepted change increments one bounded `UInt64` generation and sends the complete override set through `evaluator.render`; release removes only that address and sends the remaining set. A newer gesture cancels the prior host render task. Only a result matching the current revision and latest generation reaches `engine.replace`; stale success, cancellation and typed render failure do not alter loop, catalog, source, edit revision, line maps or the last applied override set. The applied set advances only after `PlaybackSnapshot.overrideGeneration` reports it active. Fatal worker failure preserves playback, disables all compiled controls and remains visible until a new code revision adopts.

Master controls remain the existing synchronous MainActor engine path. BPM, low-pass, delay and reverb persistent targets survive code adoption. A temporary master gesture remembers that host-owned target, writes through the existing P04 setter, and release restores it. New code issues fresh revision-scoped master addresses over the same native owners; old handles fail stale and no adoption resets or replays a master target. Editor control changes never mutate the Swift source, completion request/snapshot, undo stack, compiler anchors, evaluation revision or bar-adoption state.

Focused SessionModel Swift Testing proves: candidate ownership through delayed bar adoption; invalidation-before-discard on a newer edit; adoption-handshake availability; complete-set latest-generation replacement/release; stale and failed result preservation; fatal-worker unavailable state; source/node/Track address invalidation on code adoption; persistent master values with fresh addresses; and zero source/undo/completion changes. Integration measures audible source, subtree and Track overrides plus native masters, exact 30-millisecond handover and active generation while failed Swift edits retain the adopted worker/audio.

### P06.3 MIDI session composition

SessionModel owns internal `MIDISessionRoute`, containing optional input and note-output endpoint IDs, `sendsLoopNotes`, output channel 1...16 and `MIDIClockMode`; `.disabled` has no endpoints, notes or clock and is the default until P07 supplies device UI. `configureMIDI(_:) async throws` diffs connections, sets the independent output and clock mode through `MIDIServiceProtocol`, then starts or stops one owned `midiSchedulingTask`. Route failure retains the prior route and current audio. The injected test initializer accepts any MIDI service implementation; production constructs `CoreMIDIService` without changing evaluation or editor ownership.

The one MainActor scheduling task wakes every 50 milliseconds and requests a half-open 100-millisecond lookahead. Each wake obtains the current `PlaybackClockAnchor`; unavailable while a playing graph awaits its next callback is passed as `updateClockAnchor(nil)` and treated as normal waiting with no diagnostic. If current host time precedes the first valid anchor's presentation timestamp, SessionModel starts the first horizon at `anchor.accumulatedBeatPosition`, whose presentation time is still in the future; it does not clamp a failed negative `beat(atHostTime:)` query to zero or skip the horizon. At or after presentation it starts from the converted current beat. After a valid anchor update, SessionModel calls `schedule(loop:...)` only when loop-note output is enabled and independently calls `scheduleClock(from:through:)` only for clock-send mode. The service owns both cursors and clips overlap; anchor publication itself schedules nothing. SessionModel does not enumerate events, derive host timestamps or reset a cursor on UI refresh. Revision, override generation and tempo changes therefore schedule only the unscheduled suffix; they never duplicate an occurrence edge or clock ordinal. The maximum already-queued stale result after such a change is the declared 100-millisecond CoreMIDI horizon.

The same task reads `MIDIServiceSnapshot`. Each unseen received-clock command generation is applied once: Start sets `wantsPlayback` and calls `restartFromBeginning()` when a loop exists (or requests immediate evaluation when none exists), Continue calls `play()` without resetting position, and Stop clears `wantsPlayback` and calls `stop()`. A newly valid estimated BPM in 40...240 updates the existing live BPM/TimePitch path without evaluation; waiting, duplicate generation or invalid tempo changes nothing. MIDI service output observes the resulting stopped anchor, flushes future messages and releases tracked notes. Clock unavailable/waiting is reflected in MIDI state for P07 but does not replace editor diagnostics on every poll; a new disconnected/failed health transition publishes one diagnostic while adopted PCM continues.

`shutdown()` cancels and awaits the scheduling task, stops playback so output receives a frozen stopped anchor, then awaits MIDI service shutdown before releasing evaluation/completion owners. Shutdown, route disable and endpoint loss leave no scheduling task, stream continuation, connected source or queued service-owned note state. Focused tests use an injected service/clock to prove one scheduling owner, a future first-presentation anchor schedules its beat-zero note, nonoverlapping suffixes across refresh/rate/revision/generation, Start/Continue/Stop application, tempo without evaluation, unavailable-clock silence, one diagnostic per failure transition and cancellation/await order. The native virtual-endpoint integration proves flush/note-off on stop and retained audio on route failure. Source, revision, completion, anchors, undo and live-control overlays remain unchanged by MIDI composition.

### P07 editor controls, results and diagnostics

P07 groups the existing revision-scoped `LiveControlCatalog` into accessible source, subtree, Track and master knobs. One selected compatible pair may use the same two addresses as an XY pad; it still sends one complete override generation through SessionModel. P07.3 also adds the worker command/connection/evaluator adapter for the selected address's `PreparedControlVisualization`; selection generation is independent of audio override generation and a stale visualization never changes PCM. MIDI Learn observes the existing MIDI stream, binds one `(endpoint, channel, controller)` to one current catalog address, maps 0...127 through that descriptor's current finite presentation range, and detaches the binding from live application when that revision-scoped address becomes stale. The persisted record may remain visible but inactive under the restore rule below. The binding may store a user-expanded range within the existing control owner's admission domain; changing the viewport never clamps or narrows source/node/Track gain semantics. Playback-rate controls display the existing SessionModel BPM value while their catalog address/value remains the ratio passed to AudioLoopEngine. The same controller popover exposes the P06.4 discovered effect selector, bypass/state status, P06.5 master record start/stop/cancel and adopted-generation stem export; these controls call their existing owners and do not duplicate audio graph, tap or file lifecycle. P05.7 remains the sole precedence, release and failed-rerender authority.

Per-document host state is a bounded binary-property-list sidecar in Application Support keyed by the canonical Swift document URL. A document identity accepts a local file URL whose existing target is not a directory, plus a nonexistent local save destination; it rejects non-file URLs and existing directories. It does not require a `.swift` extension because the existing Open workflow intentionally admits plain-text files containing Swift. The state stores the selected Audio Unit identifier, bypass and validated full state plus MIDI route/Learn bindings; it never stores or rewrites Swift source, PCM, decoded samples, recording data or stem data. Each persisted Learn binding also stores the SHA-256 digest of the exact successfully adopted Swift source. On restore, the App may rebase only the address revision when that digest exactly matches the newly adopted source and the same target and parameter exist in its catalog; a numeric revision match alone has no authority. A digest mismatch or missing target remains stale and unattached until the user learns it again. Unsaved sessions retain this state only in memory.

`DocumentHostStateStore.maximumBindingCount` is `1 MiB / MemoryLayout<LearnBinding>.stride`. The store checks this count before constructing a uniqueness Set or invoking `PropertyListEncoder`; overflow is a typed invalid-state failure. The encoded binary plist must still be at most 1 MiB, so the count bound limits pre-encoding work without treating in-memory stride as serialized size. Save/open atomically write/read within that bound, validate stored identity, and leave component/endpoint/control discovery plus adopted-catalog attachment to SessionModel. Invalid or stale state never replaces source or the running graph. Recording/export destinations remain explicit per operation and are not restored automatically.

SessionModel validates each saved Learn-range endpoint through `LiveControlCatalog.validate(value:for:)` for score addresses or `AudioLoopEngine.validateMasterControl(_:value:)` for master addresses; the presentation viewport is never an admission clamp. Every adopted revision cancels and awaits the previous restore task before starting one keyed by the latest adopted revision and source digest. Cancellation propagates to and awaits an in-flight Audio Unit selection child before another restore can mutate the graph. Only that latest task may attach bindings or publish restored state. A missing sidecar queues the explicit default of a disabled MIDI route and no hosted Audio Unit for that adoption, preventing state from a prior document from bleeding into the new one. Restore failure reports the invalid entry while preserving source and adopted audio.

The existing SourceKit popover displays P07 unit/range/sample annotations without changing candidate ordering, replacement ranges or acceptance. Existing inline/side/bottom results add final onset/duration, effective MIDI pitch or explicit pitch limitation, selected-parameter curve and amplitude/pitch/filter envelope overlays from adopted renderer metadata. They preserve compiler result lines, pattern-token glow, native scrolling, source, selection and undo. Logs enables Reveal only for an exact typed `SourceDiagnosticRange`, including P07 SwiftMusic pattern failures. An ordinary Swift syntax/type failure remains visible as its bounded raw compiler log with Reveal explicitly unavailable; Logs removes the legacy `Session.swift:line` prose parser and never derives an offset from diagnostic text. Unsupported capability and adoption/worker state remain typed and distinct.

The monitor reuses post-FX master samples and adds Rendering-owned Track/Bus peak/clip envelopes plus Playback-owned CPU/dropout values. Its header presentation reuses the actual waveform/spectrum canvases at miniature scale; master telemetry and reset remain accessible from header monitoring, while detailed Track/Bus telemetry is presented in Controls; waveform and spectrum remain in the header. Native layout verification confirms the one-row music transport remains legible at the supported minimum window, the miniature signal moves with playback, and master values/reset and Controls-owned Track/Bus values are reachable without resizing the code editor. Signal processing, refresh cadence and model ownership remain unchanged. It never labels source-row peaks as Track/Bus meters. Missing owners are shown unavailable while PCM, editor text and prior diagnostics remain visible.

### Performance-model controls

SessionModel presents worker-declared performance controls beside the existing graph/native controls without converting them into `LiveControlAddress`. It stores only the adopted revision's stable model/control schema and complete mapped values. A numeric control uses its declared range and scalar or BPM role; one position control supplies both XY axes in one request and one undo-neutral UI transaction. SwiftUI `@State`/`@Bindable` may adapt these value snapshots in the App, but SwiftMusic and Core Evaluation expose only Observation, Sendable DTO and MainActor contracts.

The source-declared performance model remains owned by the retained worker. SessionModel sends a complete mapped-value generation and accepts only the matching latest rendered candidate. It then stages that PCM in AudioLoopEngine and enters one bounded performance-adoption transaction before sending the worker's exact-generation acknowledgement request. From request send through engine commit/discard, ordinary Task cancellation does not abandon the transaction: SessionModel awaits the response or existing worker watchdog, then commits the reserved token after true acknowledgement or discards it after false/fatal response. `adoptPerformance` is idempotent for the exact already-accepted revision/generation so a response-delivery race can be resolved without applying the model twice.

While that transaction is suspended, SessionModel queues at most one latest performance intent and defers code-revision transport adoption; neither may invalidate the reserved token. Stop may proceed because Playback preserves the reservation and can commit it while stopped. Document switch, close and shutdown are explicit aborts: they discard the engine reservation and kill/await the old worker before clearing transaction state, so no accepted live worker can remain ahead of an invalid token. Only after commit/discard/abort resolves may a deferred code adoption or queued performance intent start. When the engine snapshot first reports the matching completed performance generation, SessionModel calls the no-I/O `SourceEvaluator.confirmPerformance`; only a true confirmation advances `acceptedPerformanceValues`, UI state and hot-edit transfer authority. A false confirmation leaves the prior authority visible and reports the lifecycle mismatch without guessing from PCM. Before confirmation SessionModel owns at most the prior accepted values, one acknowledged generation and one latest queued complete intent. Superseded or rejected candidates are discarded from both worker and engine.

Failure or cancellation preserves the prior audibly accepted values, audio, source, undo, completion and P05.7 overlays. A BPM-role update changes the same worker render BPM and the App's effective BPM owner only through the successful two-phase replacement, without applying a second playback multiplier. On hot edit, SessionModel offers only `acceptedPerformanceValues` to the candidate after exact stable schema matching, then waits for that candidate result before code adoption. ### Inline playing literals
The adopted compiled patternText and tracked source line identify an exact, unique plain string literal on that line. Compiler-provided event patternStepIndex identifies the whitespace-delimited token within that exact literal. Only tokens whose actual events contain the transport beat glow.
