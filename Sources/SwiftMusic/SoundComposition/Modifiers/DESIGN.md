# Modifiers

## Purpose and Scope

Sound modifier declarations, processing descriptors and parameter validation. No children.

## Responsibilities and Boundaries

This directory owns the types listed below within the single SwiftMusic target. Directory moves introduce no new module or visibility boundary. Existing internal collaborators remain in the same module; audio rendering, devices and editor UI stay outside SwiftMusic.

`AudioEffect`, `BusRoutingError`, `DeclarationModifiers`, `Dynamic`, `DynamicsValidation`, `EffectModifiers`, `ExpressionModifiers`, `Legato`, `Limiter`, `MixModifiers`, `NoiseGate`, `PitchModifiers`, `Portamento`, `PortamentoDuration`, `RhythmModifiers`, `SidechainCompressor`, `SoundModifier`, `SoundParameterError`, `SourceModifiers`, `SpatialPosition`, `TrackSendPlacement`.

    -> Compilation -> RenderPlan -> host

### Effects, mix, and render plan

`AudioEffect` is an immutable enum:

```swift
case equalizer(frequencyHz: Double, gainDecibels: Double, q: Double)
case filter(kind: FilterKind, cutoffHz: Double, resonance: Double)
case compressor(thresholdDecibels: Double, ratio: Double)
case sidechainCompressor(SidechainCompressor)
case noiseGate(NoiseGate)
case limiter(Limiter)
case saturation(drive: Double)
case distortion(drive: Double)
case delay(time: MusicalTime, feedback: Double, wet: Double)
case reverb(roomSize: Double, wet: Double)
case chorus(rateHz: Double, depth: Double, wet: Double)
case flanger(rateHz: Double, delaySeconds: Double, depthSeconds: Double, feedback: Double, wet: Double)
case phaser(rateHz: Double, minimumHz: Double, maximumHz: Double, stages: Int, feedback: Double, wet: Double)
case stereoWidth(Double)
```

Frequency, Q, rate, and ratio are finite positive, with ratio at least 1. Gain and threshold are finite. Resonance and drive are finite nonnegative. Delay time is nonzero. Feedback is 0..<1; wet, room size, and depth are 0...1. Invalid values fail compilation.

`CompiledRenderNode` covers source/mix, ordinary and sidechain effects, scalar and automated gain/pan, mute/Track, declaration and Track sends, bus return, event duck and external output nodes. Every input is an explicit node ID; `CompiledSound.renderNodes` is dependency ordered and node IDs are array indices, while `rootNodeIDs` names final main-signal roots and routed output sinks. The exact P05.1 signal, P05.2 bus and P05.3 dynamics cases are owned by their sections below.

An `output` node is a terminal routing sink and cannot be an input to another render node. Parallel merging keeps output sinks as separate final roots and mixes only unrouted main-signal roots: zero main roots produce no mix, one passes through, and multiple produce one mix. Thus `Track { Sample("a").output("bus"); Sample("b") }` has the output sink and the unrouted sample as separate final roots and never mixes the sink back into the main signal.

Effects, gain, pan, mute, send, and output wrap a subtree only while it has no terminal output sink. Applying an otherwise valid one outside a subtree that already contains an output sink throws `SoundCompilationError.invalidParameter` describing processing after output; invalid scalar or name input may be rejected first by the same typed case. Processing must be declared before routing. Event transforms and source settings remain legal outside output because they alter events or descriptors without consuming a render root. Chained effects preserve source -> first -> second, while an effect on a multi-source Track produces sources -> mix -> effect. Gain is finite nonnegative, pan finite -1...1, send level finite nonnegative, and route names non-whitespace. Send preserves main flow and remains consumable while describing its side route.

## Ordered Mix and Effect Performance

P04 preserves the existing distinction between event `gain`/`pan` values and ordered subtree render nodes. `GainPattern` and `PanPattern` stay per-event before source mixing. Existing `.gain(Double)`, `.pan(Double)` and `.muted()` remain graph operations at their declaration position. Chained effects remain dependency ordered and a multi-source subtree is mixed once before its enclosing effect. SwiftMusic validates immutable descriptors and graph topology but performs no DSP or live parameter mutation.

P04.1 retains all existing `AudioEffect` cases and adds `case saturation(drive: Double)`. EQ frequency and Q are finite positive and gain dB finite; saturation and distortion drive are finite nonnegative; delay time is positive, feedback finite in `0..<1` and wet finite in `0...1`; reverb roomSize and wet are finite in `0...1`. Zero saturation/distortion drive and zero wet are neutral. Existing post-mix filter, compressor and chorus descriptors remain source compatible but are still explicit renderer-unsupported cases until their owning later sprint. Repeating EQ nodes is the public multi-band composition mechanism; P04 adds no separate EQ collection or mutable effect identity.

P04.3 makes a Track an explicit ordered mix boundary without changing event timing. `trackLevel(_ value: Double)`, `trackPan(_ value: Double?)`, `trackMuted(_ value: Bool = true)` and `trackSolo(_ value: Bool = true)` return a copied Track descriptor; defaults are level one, nil pan, false mute and false solo. Level is finite nonnegative. Optional pan is finite in `-1...1`, where nil is byte-preserving bypass and explicit zero uses the established equal-power law. Validation remains compiler-owned because these copy operations are nonthrowing. `CompiledTrack` carries `level`, `pan`, `isMuted`, `isSoloed` and optional dependency-ordered `renderNodeID`. After visiting and mixing all nonempty main-signal content inside a Track, including nested Track nodes, the compiler appends `CompiledRenderNode.track(input:trackID:)`, records that node ID and returns it before any modifier declared outside the Track. An empty Track preserves its metadata with nil `renderNodeID` and allocates no render node. For compatibility, output-routed roots inside a default Track remain transparent and are preserved beside its wrapped main-signal root; a Track with any nondefault level, pan, mute or solo setting and an output-routed root fails with the existing processing-order error instead of silently bypassing its setting. Existing generic gain/pan/mute declarations retain their exact graph positions.

If any Track is soloed, the renderer derives two sets from the immutable `CompiledTrack` hierarchy before rendering node buffers. The source-audible set is every soloed Track and its descendants; only events directly owned by those tracks may render, and untracked or ancestor-owned direct sources are silent. The transit-enabled set adds ancestors needed to carry those already-filtered descendant signals through enclosing track nodes. A transit ancestor does not make its own directly owned source audible. Unrelated track nodes are silent. Explicit mute always wins at its track node, including on an ancestor of a soloed Track, and therefore blocks that complete subtree. A transit-enabled track node still applies its declared child signal, level and optional pan before its mute/solo gate. Nested `parentID`, innermost event `trackID`, source identity, event/provenance arrays and live-event recurrence remain unchanged. Nil/default track settings preserve PCM exactly; the new node and optional `renderNodeID` are the stable authorities later meters and live track controls may address.

Compiler verification uses Swift Testing to prove every P04.1 success/failure and exact effect order, unchanged existing cases, unsupported-case preservation, zero-neutral descriptors, track node placement for single/mixed/nested content, empty and default routed-Track compatibility, typed rejection of nondefault settings after routing, level/pan/mute/solo precedence, solo source ownership versus ancestor transit, processing outside Track order, unchanged events/provenance and existing graph/node/depth bounds.

## Named Bus Routing

P05.2 preserves `Sound.send(to:level:)` as a declaration-position dry-preserving send and `output(_:)` as a terminal external sink. It adds `TrackSendPlacement.preFader` and `.postFader`, plus `Track.send(to:level:placement:) -> Track`; pre-fader taps the Track content before its level/equal-power pan, post-fader taps after them. Both placements obey the Track's solo eligibility and mute, and any muted ancestor suppresses the contribution, so pre-fader never bypasses the established complete-subtree mute invariant. Existing declaration-position Sound sends keep their graph position and do not acquire Track-fader semantics. Send level remains finite nonnegative and zero is an exact no-contribution branch.

`BusReturn(_ name: String)` is an eventless Sound primitive for one internal named-bus sum. It may be declared before or after senders and may receive ordinary effects/gain/pan/routing modifiers. A bus with a `BusReturn` requires exactly one return and at least one send; duplicate returns, a return without sends, invalid names and bound failures are typed compilation errors. The new `Track.send` requires a matching BusReturn and otherwise fails compilation as `BusRoutingError.missingReturn(bus)`; it has no compatibility exception. For source compatibility, only an existing declaration-position `Sound.send` without a BusReturn still compiles to its unchanged send node and represents an unresolved external contribution; MusicPlaygournd rejects that capability explicitly before rendering rather than discarding it silently. Internal bus names and external `output` names are separate namespaces. The native editor backend accepts unrouted roots and `output("main")` as its stereo main result; other external output names remain explicit capability failures until multi-output/stem ownership in P06.

`CompiledRenderNode.send(input:bus:level:)` remains the declaration-position identity/tap node. P05.2 adds `trackSend(input:bus:level:trackID:placement:)` and `busReturn(bus:inputs:)`; the return inputs identify contributing send-node IDs in stable declaration order. After the ordinary one-pass body visit, the compiler resolves bus names, adds return dependencies, performs a stable topological sort over every node kind, and remaps node inputs, roots and `CompiledTrack.renderNodeID` once. A return may feed another send, but any self or cross-bus cycle is rejected before CompiledSound is returned. Successful `renderNodes` remains dependency ordered and a node is evaluated once even when its signal feeds dry and bus consumers. Event timing, source/track identity, live recurrence and provenance remain unchanged.

`SoundCompiler.Limits.maximumBuses` is a source-compatible defaulted initializer field; MusicPlaygournd sets it to 32. Sends continue to consume the existing render-node limit. Compiler resolution uses checked node/edge counts and no recursive unbounded traversal. LoopRenderer performs a liveness pass before PCM allocation, retains each full stereo node buffer until its final dry/send/return consumer, and rejects a graph requiring more than 32 simultaneously live buffers. This ceiling is derived from the existing maximum 32 prepared source rows rather than an unbounded per-node cache. Buffer ownership and bus accumulation stay off the audio callback; final AudioTransport still owns one interleaved PreparedLoop.

Compiler Swift Testing proves source compatibility for existing send/output graphs, forward-declared returns, stable remapping across effects/Track nodes/P05.1 automation, pre/post-fader placement, duplicate/empty returns, typed unmatched-Track-send failure, legacy unmatched-Sound-send graph identity plus renderer rejection, maximum buses/nodes/edges and concrete self/cross cycles. Renderer tests prove one evaluation per shared node, exact dry preservation, multiple-send summation order, zero send, Track level/pan pre/post difference, solo source ownership, muted Track and muted-ancestor suppression, bus effects, main output selection, typed non-main output failure, 32-live-buffer admission/rejection, finite/seamless PCM and unchanged events/provenance. One evaluated named-bus session reaches nonzero native playback and a routing failure retains the previous revision.

## Dynamics and Event Ducking

P05.3 keeps the existing `AudioEffect.compressor(threshold:ratio:)` and `case compressor(thresholdDecibels:ratio:)` source compatible and gives that previously unsupported descriptor an instantaneous self-detected compressor implementation with zero knee. The explicit dynamics API adds `SidechainCompressor`, `NoiseGate` and `Limiter` public `Sendable`, `Equatable`, `Hashable` value descriptors and the corresponding `AudioEffect.sidechainCompressor(_:)`, `.noiseGate(_:)` and `.limiter(_:)` cases. `SidechainCompressor` stores public immutable `thresholdDecibels`, `ratio`, `attackSeconds`, `releaseSeconds`, `kneeDecibels` and `sidechainBus`; its throwing `init(threshold:ratio:attack:release:knee:sidechainBus:)` accepts `Decibels`, `Duration`, `Decibels` and `String?`, with only `sidechainBus` defaulting to nil. Nil selects its processed input and a name selects the actual resolved BusReturn PCM. `NoiseGate` stores `thresholdDecibels`, `attackSeconds` and `releaseSeconds`; its throwing `init(threshold:attack:release:)` has no defaults. `Limiter` stores `ceilingDecibels` and `releaseSeconds`; its throwing `init(ceiling:release:)` has no defaults. Thresholds are finite, ratio is finite and at least one, knee is finite nonnegative dB, durations must convert to finite nonnegative seconds, limiter ceiling is at most 0 dBFS, and a sidechain name is nonblank. Initializers reject invalid descriptors eagerly; the compiler revalidates legacy compressor values and all graph references. No invalid declaration bypasses DSP.

`Sound.duck(targetBus:depth:attack:recovery:)` accepts `String`, `Decibels`, `Duration`, `Duration` with no defaults and returns a nonthrowing declaration modifier whose compiler validation requires a nonblank BusReturn name, finite nonpositive depth dB, finite nonnegative attack and finite positive recovery. It preserves the trigger Sound's audio and attaches the rule to every final event produced by that fragment; outer rhythm/note/repeat/live expansion therefore creates real trigger onsets, while a rule outside those generators applies to their final emitted events in ordinary inner-to-outer order. After final stable event sorting, `CompiledSound.eventDucks` contains public immutable `CompiledEventDuck(triggerEventIndex:targetBus:depthDecibels:attackSeconds:recoverySeconds:)` values in declaration/event order; each trigger index names that final `CompiledSound.events` entry. Internal per-event pending rules survive cloning and are flattened only after sorting, so an index cannot drift. The renderer maps the trigger beat with its existing `floor(startBeat * 60 / BPM * 44_100)` onset rule, then linearly interpolates amplitude gain from one to `pow(10, depthDecibels / 20)` over the physical attack seconds and back to one over the physical recovery seconds; zero attack applies the depth gain at the onset frame. Overlapping rules targeting the same bus use the deepest active attenuation, rather than multiplying depths. Finite recovery is clipped only by absence of target-bus PCM; seamless recovery folds these frames modulo the canonical window and its full attack-plus-recovery span must not exceed that window.

The compiler resolves event-duck targets and external sidechains only after P05.2 bus returns. A target return is followed by one `CompiledRenderNode.eventDuck(input:rules:)`, where `rules` are stable indices into `CompiledSound.eventDucks`; all existing downstream users are remapped to that node, so ducking precedes modifiers declared on `BusReturn`. Multiple rules for one return share that boundary in stable declaration/event order. A named sidechain always reads this post-duck BusReturn boundary before effects or other modifiers declared on the return; it never resolves to that return's final downstream chain. A `SidechainCompressor` with a bus compiles as `CompiledRenderNode.sidechainEffect(input:sidechain:compressor:)`, with both IDs preceding the node after stable topological resolution; one with nil sidechain remains an ordinary `.effect(input:effect:)`. Missing returns, duplicate or inconsistent rule identity, a sidechain dependency cycle, invalid event/rule indices and the existing node/edge/bus bounds are typed compilation errors. Duck timing depends only on immutable compiled event onsets, so a trigger may belong to its target bus without creating an audio graph cycle; a compressor sidechain consumes PCM and must obey graph acyclicity.

All dynamics use the linked stereo peak `max(abs(left), abs(right))` as detector input, with no channel-specific image shift. For detector dB `x`, threshold `T`, ratio `R`, knee width `W` and `d = x - T`, compressor gain dB is zero below `-W/2`, `(1/R - 1) * d` above `W/2`, and `(1/R - 1) * pow(d + W/2, 2) / (2W)` inside a positive-width knee; `W == 0` uses the corresponding hard threshold. It has no makeup gain and smooths the detector with `exp(-1 / (seconds * sampleRate))`, using attack while level rises and release while it falls; zero duration is an explicit instantaneous branch. Gate opens toward unity with attack and closes toward zero with release. Limiter attacks instantaneously so every output sample is at or below its declared linear ceiling and releases toward unity with its declared release. Silence is negative infinity dB by definition, not an epsilon-dependent level. Dynamics scale only their processed input and add no output horizon or synthetic events.

Finite processing starts from neutral bounded state: detector zero, compressor/limiter gain one and gate gain zero. Seamless processing solves the scalar periodic detector/gain state against the complete circular input instead of resetting at the seam. The renderer brackets the valid scalar interval and performs at most 64 deterministic bisection passes, then accepts only a finite boundary residual within `1e-12 * max(1, stateMagnitude)`; absence of a unique verified state is a typed `nonPeriodicDynamicsState` failure. Event ducking is a direct circular envelope and needs no iterative state. At most 32 dynamics/duck nodes and 1,024 duck rules may be admitted under the existing node/event ceilings; solver scans and buffers remain off the audio callback and all intermediate gain/PCM values must be finite.

Swift Testing proves legacy compressor compatibility, constructor/compiler failures, hard/soft-knee reference gains, attack/release trajectories, stereo linking, gate open/close, strict limiter ceiling/release, event-onset duck attack/recovery/overlap and source provenance, external bus selection and concrete cycle rejection. Finite fixtures prove neutral initial state and unchanged horizons; seamless fixtures prove first/last detector state and PCM continuity or the exact periodic-state failure. Named-bus fixtures distinguish dry target, post-return effects and sidechain audio, assert existing graph/live-buffer bounds, and pass one evaluated duck-plus-sidechain loop through native playback while a dynamics failure retains the prior revision.

## Modulation Effects and Post-mix Filter

P05.6 makes the existing `AudioEffect.filter(kind:cutoffHz:resonance:)` and `.chorus(rateHz:depth:wet:)` descriptors audible without changing their stored cases. Typed factories are `filter(kind: FilterKind, cutoff: Frequency, resonance: Double)` and `chorus(rate: Frequency, depth: Double, wet: Double)`. Post-mix filter supports every existing `FilterKind` through RBJ low-pass, high-pass, constant-peak band-pass and notch coefficients with `Q = 0.5 + resonance`, preserving valid legacy resonance zero. Notch uses normalized `b0 = b2 = 1 / a0` and `b1 = -2 * cos(w0) / a0` with the standard shared denominator. Cutoff must be below renderer Nyquist; resonance remains finite nonnegative. Like EQ, finite filter owns only its input horizon, begins at zero state and deliberately discards residual IIR state rather than claiming a tail; seamless filter solves and verifies its periodic biquad state.

New direct enum cases are `flanger(rateHz:delaySeconds:depthSeconds:feedback:wet:)`, `phaser(rateHz:minimumHz:maximumHz:stages:feedback:wet:)` and `stereoWidth(Double)`. Their typed factories are `flanger(rate: Frequency, delay: Duration, depth: Duration, feedback: Double, wet: Double)` and `phaser(rate: Frequency, minimum: Frequency, maximum: Frequency, stages: Int, feedback: Double, wet: Double)`; Duration is converted to checked finite seconds. Flanger requires positive delay, nonnegative depth, `delay > depth`, finite feedback with `abs(feedback) < 1`, and wet in `0...1`. At render rate its minimum delay `delay - depth` must be at least one frame. Phaser requires `minimum < maximum < Nyquist`, 1...32 stages under an explicit per-node DSP-state bound, finite `abs(feedback) < 1`, and wet in `0...1`. Stereo width is finite nonnegative; width one is exact bypass, zero is mono, and processing uses `mid = (L + R) / 2`, `side = (L - R) / 2 * width`, then `L = mid + side`, `R = mid - side`.

Chorus uses a sinusoidal delay of `15 ms + sin(phase) * 10 ms * depth`, right-channel phase offset by one quarter cycle, no feedback, and dry/wet `dry * (1 - wet) + delayed * wet`. Flanger uses the same fractional linear-interpolated delay-line ownership with its declared center delay/depth and feeds the delayed sample back by the declared coefficient. Phaser cascades the declared number of first-order time-varying all-pass stages and then feeds the processed output back by its coefficient. At frame `n`, `a[n] = (tan(pi * frequency[n] / sampleRate) - 1) / (tan(pi * frequency[n] / sampleRate) + 1)` and each stage computes `y[n] = a[n] * x[n] + x[n-1] - a[n] * y[n-1]`; it must use the current coefficient for both current terms, never the prior frame's coefficient. Each channel/stage owns exactly two Double history values, previous input and previous output. Graph declaration order remains authoritative, every channel owns independent delay/filter state, and all coefficient, interpolation, feedback and PCM arithmetic remains Double until checked Float output.

`Sound.tremolo(rate: ModulationRate, depth: Double, waveform: LFOWaveform = .sine)` lowers to the existing graph-position `GainAutomation` from `1 - depth` to one. `Sound.vibrato(rate: ModulationRate, depth: Semitones, waveform: LFOWaveform = .sine)` lowers to the existing outermost-wins source `PitchAutomation` from negative to positive depth. Tremolo depth is finite in `0...1`; vibrato depth is finite nonnegative. A zero-depth call is an identity modifier: tremolo appends no node, while vibrato neither replaces an existing pitch automation nor invokes pitched-source capability rejection. A nonzero vibrato follows existing synthesizer/rooted-file/rooted-bank support and explicit procedural-sample/white-noise failures. Both retain P05.1 synchronized-period compilation and physical-Hz seam validation rather than adding another clock owner.

Finite chorus extends its input by the declared maximum delay `15 ms + 10 ms * depth` when wet is nonzero; depth zero therefore retains the audible 15 ms fixed-delay chorus rather than claiming a 25 ms tail. Finite flanger tail taps are bounded before allocation. Let `maximumDelayFrames = (delay + depth) * sampleRate`; feedback zero owns one tap, otherwise `count = floor(log(1e-5) / log(abs(feedback))) + 1`. The conservative last owned frame is `count * ceil(maximumDelayFrames)`, which includes the upper support frame of every fractional linear-interpolated tap; using `ceil(count * maximumDelayFrames)` is insufficient and forbidden. The checked maximum delay and derived integer-frame tail must fit the existing 16-second effect ceiling. Finite flanger delay state starts zero. Phaser adds no horizon and, like filter/EQ, discards its finite residual state. Tremolo, vibrato and stereo width add no tail.

For seamless chorus, flanger and phaser, `rateHz * (frameCount / 44_100)` must be a finite integer number of physical cycles; finite rendering accepts any otherwise valid rate. Chorus reads the input circularly and needs no feedback state. Flanger feedback and time-varying phaser state must converge to a verified periodic boundary within at most 64 complete-window passes; the renderer rejects a nonfinite state or residual above `1e-12 * max(1, stateMagnitude)` as typed nonperiodic modulation state. Post-mix filter reuses the established exact periodic biquad solver. At most 32 modulation-effect nodes are admitted; phaser's 32 stages bound its small Double state, delay/tail buffers remain under existing frame/live-buffer bounds, and all work stays off the audio callback.

Wet zero for chorus/flanger/phaser, tremolo/vibrato depth zero and stereo width one dispatch to exact input/no-op branches after descriptor validation. No unsupported effect becomes silence or a master AVAudioUnit substitute. Swift Testing proves typed/raw constructor validation, legacy filter/chorus behavior, RBJ filter response, chorus/flanger fractional-delay frames and stereo phase, flanger tail count/causal minimum, phaser endpoint/stage/feedback response, width matrix, declaration order and every neutral identity. Finite tests assert owned horizons; seamless tests assert physical-cycle rejection and verified state/PCM boundary or typed failure. Vibrato fixtures measure oscillator and rooted-sample pitch while tremolo measures gain through existing automation; one evaluated ordered chain reaches native playback and invalid modulation retains the prior revision.

### Nonthrowing parameter declarations

Sound's scalar envelope, filter/pitch envelope, unison and duck overloads capture immutable Sendable arguments in an internal parameter declaration. No validation or user callback executes while declaring the body. Compilation resolves the declaration using the existing validating value initializers, then applies the existing modifier case. The closure is internal, has no external resources and is retained only with the immutable sound/live program. Invalid values fail through the existing located compilation error at the modifier call site; no fallback or trap is introduced. Existing eager value initializers and compiled descriptors remain unchanged. Live emission uses the same resolution path. DeclarationModifierTests owns eager/deferred equivalence and located invalid-value checks; the Playground template/PCM integration verifies the consumer.
